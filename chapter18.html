Chapter 18: Quantum Kernel Methods

How quantum computers can transform data into new mathematical representations, how kernel methods learn from those representations, and why a quantum kernel is not automatically better than a classical one.

Chapter Overview

Imagine that you have to separate pictures of cats from pictures of dogs. In one representation, the two groups may overlap so much that drawing a straight line between them is difficult. But after transforming the data into a more useful representation, the groups might become easier to separate. Kernel methods are built around this idea.

Quantum kernel methods bring quantum circuits into this process. A quantum circuit transforms a classical input into a quantum state. We then compare the resulting states to estimate how similar the original inputs are in the quantum representation. A classical learning algorithm, such as a support vector machine, can use these similarities to make predictions.

The central question is not simply whether a quantum computer can represent data. It is whether the representation produced by a quantum circuit helps solve a particular learning problem more effectively than practical classical alternatives.

Learning objectives

  • Understand classical kernels and feature maps.
  • Connect quantum states with feature spaces and inner products.
  • Calculate a quantum kernel using state overlaps and measurements.
  • Understand quantum kernel estimation and support vector machines.
  • Learn how kernels can be trained and aligned with a learning task.
  • Recognise concentration effects, noise, computational costs and other pitfalls.
  • Build a small quantum-kernel classification experiment using Python.
The big picture: A quantum circuit supplies a feature representation. The kernel measures similarity in that representation. A classical learning algorithm uses the similarities to learn a decision boundary.

18.1 Kernels and Feature Maps Revisited

18.1.1 Why do we need feature maps?

A machine-learning dataset usually begins with ordinary numbers. For example, a student dataset might contain hours studied and attendance percentage. A fraud-detection dataset might contain transaction amount, transaction time and account activity.

We call each example an input vector. If an example has two features, we can represent it as:

x = (x₁, x₂) Here, x₁ and x₂ are the two measured properties of one example.

A learning algorithm tries to discover a relationship between these features and the correct output. A simple classifier may draw a straight line in two dimensions, or a plane in three dimensions, to separate two classes.

However, real data is not always separated by a straight line. Consider points arranged in two concentric circles: one class occupies the inner circle, and the other occupies the outer ring. A straight line cannot separate the two classes perfectly.

One solution is to construct new features. Instead of using only x₁ and x₂, we might include their squared values or a function of their distance from the origin. The transformed representation can reveal patterns that were difficult to see in the original data.

18.1.2 What is a feature map?

A feature map is a mathematical transformation that converts an input into a representation that may be more useful for learning. We write it as φ(x), pronounced "phi of x".

φ : X → F A feature map takes an input from the original space X into a feature space F.

For a simple example, suppose an input contains one number, x. A feature map could transform it into:

φ(x) = (x, x²)

The original input has one coordinate, but the transformed representation has two. This is useful because a relationship that is complicated in the original space may become simpler in the transformed space.

A feature map does not automatically improve a model. Its usefulness depends on whether the transformation exposes information relevant to the task. A poor representation can make learning harder rather than easier.

18.1.3 What is a kernel?

Suppose we transform two inputs, x and z, into feature vectors φ(x) and φ(z). One way to compare them is to calculate their inner product. In ordinary Euclidean space, the inner product multiplies corresponding coordinates and adds the results.

K(x, z) = φ(x) · φ(z) The kernel measures similarity through an inner product in the feature space.

This function K is called a kernel when it satisfies the mathematical conditions required of a valid kernel for the learning method being used. For the standard real-valued positive-semidefinite kernels discussed here, the Gram matrix must be positive semidefinite.

The important observation is that we may be able to calculate K(x, z) without explicitly constructing the entire transformed vector φ(x). A function that directly calculates the inner product is called a kernel function.

18.1.4 A numerical example

Consider the feature map:

φ(x) = (x, x²)

For x = 2 and z = 3, the transformed vectors are (2, 4) and (3, 9). Their inner product is:

K(2, 3) = 2 × 3 + 4 × 9 = 42

We can calculate the same value directly from the original inputs:

K(x, z) = xz + x²z²

Substituting x = 2 and z = 3 gives 6 + 36 = 42. We have obtained the inner product in the transformed space without separately constructing the transformed vectors.

Notice that a kernel value is not necessarily a probability. It can be larger than one or even negative for some valid kernels. A quantum fidelity kernel, introduced later, has a different range because it is based on squared state overlap.

18.1.5 Common classical kernels

Kernel Definition General intuition
Linear K(x,z) = x · z Compares the original feature vectors directly.
Polynomial K(x,z) = (γx · z + r)d Captures interactions between features up to a degree controlled by d.
Gaussian RBF K(x,z) = exp(−γ‖x − z‖²) Assigns high similarity to nearby inputs and lower similarity to distant inputs.

The Gaussian radial basis function, or RBF, kernel is especially useful because it can represent nonlinear decision boundaries without explicitly creating a very large feature vector.

Connection to quantum computing: Classical kernel methods already provide a way to learn from complicated feature spaces. Quantum kernel methods replace or supplement the classical feature map with a quantum-state preparation circuit.

18.2 Quantum Feature Maps and Hilbert Space

18.2.1 From a classical vector to a quantum state

A quantum feature map is a quantum circuit that depends on the classical input. We represent it as U(x). When the circuit acts on a fixed initial state, usually the all-zero state, it produces a state that depends on x.

|φ(x)⟩ = U(x)|0⟩⊗n U(x) is the input-dependent circuit, and n is the number of qubits.

The notation |0⟩⊗n means that all n qubits begin in the computational basis state zero. For two qubits, the initial state is |00⟩. The feature map applies gates to this state to encode the input.

A quantum state is described by amplitudes. For n qubits, a pure state can be written as a superposition of 2ⁿ computational basis states:

|φ(x)⟩ = Σj=02ⁿ−1 aj(x)|j⟩

The complex amplitude aj(x) describes the contribution of basis state |j⟩. The squared magnitudes of the amplitudes sum to one:

Σj |aj(x)|² = 1

This growing state space is one reason quantum feature maps are interesting. With n qubits, the state description contains 2ⁿ complex amplitudes. A carefully designed circuit can create relationships between amplitudes that are difficult to reproduce using certain restricted classical representations. But the size of the state vector alone does not prove a practical computational advantage.

18.2.2 What is a Hilbert space?

A Hilbert space is a vector space equipped with an inner product and a completeness property. In finite-dimensional quantum mechanics, it is enough for us to think of it as a complex vector space in which quantum states can be represented and compared using inner products.

Quantum states are vectors in this space. The inner product of two states is written as:

⟨φ(x)|φ(z)⟩

This quantity is generally complex. Its magnitude tells us how much the two state vectors overlap. The squared magnitude has a direct operational meaning: it is the probability of obtaining the all-zero outcome after applying the inverse of one state-preparation circuit to the other prepared state, assuming ideal operations and measurement.

18.2.3 The quantum kernel

A common quantum kernel is the fidelity kernel:

K(x,z) = |⟨φ(x)|φ(z)⟩|² The fidelity kernel measures the squared overlap between two pure quantum states.

This formula connects the quantum circuit directly to classical kernel learning. Each classical input becomes a quantum state, and the similarity between two inputs is estimated by comparing those states.

Because the states are normalised, the fidelity kernel lies between zero and one:

  • K(x,z) = 1: the states are identical up to a global phase.
  • K(x,z) = 0: the states are orthogonal and perfectly distinguishable in the ideal pure-state setting.
  • Values between zero and one: the states have partial overlap.

This does not mean that two inputs with a kernel value of 0.9 must belong to the same class. Similarity is a property of the chosen representation; classification also depends on the training labels and the learning algorithm.

18.2.4 Why the quantum kernel is a valid kernel

Consider the pure-state density operator:

ρ(x) = |φ(x)⟩⟨φ(x)|

An operator is a linear transformation on a vector space. The density operator here describes the pure quantum state in a form that is useful for calculating overlaps. The fidelity kernel can be written as:

K(x,z) = Tr[ρ(x)ρ(z)]

Here, Tr means the trace, which is the sum of the diagonal entries of a matrix. This expression is the Hilbert–Schmidt inner product of the two density operators. For any set of inputs, the resulting Gram matrix is positive semidefinite, making this a valid kernel.

The quantum feature map can therefore be viewed as an ordinary feature map into a space of operators. This observation is important because it explains why a quantum kernel can be used by a classical support vector machine.

18.2.5 A one-qubit example

Let us encode a real number x into one qubit using a rotation about the Y-axis:

RY(x) = [ cos(x/2) −sin(x/2) ]
[ sin(x/2) cos(x/2) ]

Starting with |0⟩, the circuit prepares:

|φ(x)⟩ = cos(x/2)|0⟩ + sin(x/2)|1⟩

For another input z, the inner product is cos((x − z)/2). Therefore:

K(x,z) = cos²((x − z)/2)

If x and z are equal, the kernel is one. If their difference is π, the kernel is zero. This is a simple example of how a circuit defines a particular similarity measure.

Important: A quantum circuit does not automatically create a useful feature map just because it uses qubits. The encoding gates, entangling gates, number of layers and input scaling all influence the similarity function that the model receives.

18.3 Quantum Kernel Estimation

18.3.1 Turning the formula into a circuit

We know the mathematical definition of a fidelity kernel. The next question is practical: how can a quantum computer estimate its value?

Assume the feature map U(x) prepares |φ(x)⟩. To estimate K(x,z), we prepare the state for z and then apply the inverse circuit for x. The resulting state is:

U(x)† U(z)|0⟩⊗n

The dagger symbol denotes the conjugate transpose, corresponding to the inverse of a unitary circuit. The order of operations matters: the circuit for z is applied first, followed by the inverse circuit for x.

If the two feature states are identical, the inverse circuit returns the system to the all-zero state. If the states are orthogonal, the ideal all-zero probability is zero.

Initial state |0...0⟩
→
Apply U(z)
Apply U(x)†
→
Measure all qubits
Count all-zero outcomes
→
Estimate K(x,z)

18.3.2 Why do we measure many times?

A quantum measurement produces an individual outcome, not a direct readout of every probability in the state. The circuit must therefore be run repeatedly. Each execution is commonly called a shot.

Suppose we run the circuit 1,000 times and observe the all-zero outcome 720 times. The estimated kernel is:

K̂(x,z) = 720 / 1000 = 0.72

The hat over K indicates an estimate rather than the exact theoretical value. If the ideal probability is p and we use N independent shots, the estimator is the sample proportion. Its standard error is:

SE = √[p(1 − p)/N]

Since p is usually unknown, we can estimate the standard error by substituting the observed proportion p̂. The uncertainty generally decreases in proportion to 1/√N. To reduce the statistical error by approximately half, we need about four times as many shots.

This is a fundamental practical trade-off. More shots can improve precision, but they increase circuit executions and computational cost. Hardware noise can introduce additional bias that more shots alone will not remove.

18.3.3 Constructing a kernel matrix

Machine-learning datasets contain many examples, not just two. Suppose the training set is:

D = {(x₁,y₁), (x₂,y₂), ..., (xₘ,yₘ)}

We calculate the kernel between every pair of training inputs. This produces an m × m Gram matrix:

Kij = K(xᵢ,xⱼ)

For a fidelity kernel, the diagonal entries are one in the ideal case because every state has unit overlap with itself. The matrix is symmetric for real-valued fidelity kernels:

K(xᵢ,xⱼ) = K(xⱼ,xᵢ)

With m training examples, there are m² entries in a full matrix, although symmetry means that only m(m + 1)/2 distinct entries need to be estimated if the diagonal is included. Even this can become expensive for large datasets.

18.3.4 Training and test kernel matrices

When a model is evaluated on new examples, it needs similarities between each test input and every training input. If there are t test examples, the test kernel matrix has dimensions t × m.

Matrix Dimensions Purpose
Training Gram matrix m × m Used to fit the classifier.
Test kernel matrix t × m Used to predict labels for unseen examples.

It is essential to use the same feature map and circuit settings for training and test kernels. Otherwise, the model may be trained and evaluated using different notions of similarity.

18.3.5 Estimation on real quantum hardware

Real hardware adds complications beyond sampling uncertainty. Gates may be imperfect, measurements may be biased, and qubits may lose coherence while the circuit is running. These effects can change the observed kernel values.

A matrix estimated from noisy measurements may fail to be positive semidefinite, even though the exact fidelity kernel is valid. Depending on the application, practitioners may symmetrise the matrix, project it towards a positive-semidefinite matrix or use another carefully justified correction. These operations can change the effective kernel and should be reported during evaluation.

Practical lesson: Quantum kernel estimation is not a single calculation. It is a data-processing pipeline involving circuit construction, repeated measurements, statistical estimation, matrix construction and validation.

18.4 Quantum Support Vector Machines

18.4.1 What does an SVM do?

A support vector machine, or SVM, is a supervised-learning algorithm. It learns from labelled examples and attempts to separate the classes using a decision boundary.

Imagine red and blue points scattered on a sheet of paper. Many lines might separate the two groups. An SVM prefers a boundary that maximises the margin, which is the distance between the boundary and the closest training points from the two classes.

Those closest points are called support vectors. They are especially important because they help determine the final decision boundary.

18.4.2 Why use a kernel with an SVM?

A linear SVM works with a linear boundary in its feature representation. A kernel SVM can create nonlinear boundaries in the original input space by comparing examples through a kernel function.

The kernel trick allows the SVM optimisation to depend on inner products between examples rather than on explicit feature vectors. This makes kernel methods practical even when the feature representation is large or conceptually infinite-dimensional.

18.4.3 The SVM optimisation problem

For a binary classification problem, labels are usually represented as yᵢ ∈ {−1,+1}. A soft-margin SVM balances a wide margin against violations of the classification constraints. Its standard dual optimisation problem is:

Maximise: Σᵢ αᵢ − ½ ΣᵢΣⱼ αᵢαⱼyᵢyⱼK(xᵢ,xⱼ)

Subject to:

0 ≤ αᵢ ≤ C,    Σᵢ αᵢyᵢ = 0

Here, αᵢ are learned coefficients, and C controls the trade-off between a large margin and training errors. The kernel K(xᵢ,xⱼ) supplies the similarities required by the optimisation.

In a quantum kernel SVM, we replace a classical kernel with the estimated quantum kernel. The optimisation itself can still run on an ordinary classical computer.

18.4.4 The complete workflow

Classical labelled data
→
Quantum feature map
Estimate pairwise fidelities
→
Build Gram matrix
Train classical SVM
→
Predict unseen labels

The quantum circuit does not need to learn the labels directly in this workflow. Instead, it supplies a similarity matrix. The SVM learns how to use that matrix to distinguish the classes.

18.4.5 Does the quantum kernel make the SVM faster?

Not necessarily. The classical SVM optimisation still has its own computational cost. Moreover, estimating a quantum kernel may require many circuit executions. If the dataset is large, constructing the Gram matrix can become the dominant expense.

Quantum advantage would require evidence that the complete quantum workflow offers a meaningful improvement over strong classical methods under a fair comparison. It is not enough to show that a quantum state has many amplitudes or that a small quantum model classifies a dataset successfully.

Remember: A quantum kernel SVM is usually a hybrid algorithm. Quantum hardware estimates similarities, while a classical computer performs the SVM optimisation and often handles the remaining data-processing steps.

18.5 Kernel Alignment and Trainable Kernels

18.5.1 The problem with a fixed feature map

Consider a quantum feature map that is selected before training begins. It might be based on rotation gates, entangling gates and a fixed number of circuit layers. The resulting kernel is fixed once these choices are made.

But not every feature map suits every dataset. A circuit may produce representations that are mathematically rich but fail to distinguish the classes we care about. Another circuit might produce a more useful structure for the same problem.

This motivates trainable quantum kernels. Instead of keeping every circuit parameter fixed, we introduce parameters that can be adjusted using the training data.

18.5.2 Parameterised quantum feature maps

Let θ represent trainable circuit parameters. The state becomes:

|φ(x;θ)⟩ = U(x;θ)|0⟩⊗n

The associated fidelity kernel is:

Kθ(x,z) = |⟨φ(x;θ)|φ(z;θ)⟩|²

Changing θ changes the states and, consequently, the similarities between data points. Training the kernel means searching for parameters that produce a useful similarity structure for the task.

18.5.3 What is kernel alignment?

Kernel alignment measures how well a kernel matrix agrees with a target structure derived from the training labels. For binary labels, one simple target matrix is:

Tij = yᵢyⱼ

If two examples have the same label, their product is +1. If their labels differ, their product is −1. This gives us a simple indication of the relationships we would like the model to learn.

A common normalised alignment measure for a real kernel matrix K and target matrix T is:

A(K,T) = ⟨K,T⟩F / (‖K‖F ‖T‖F)

The Frobenius inner product, written ⟨K,T⟩F, is the sum of the products of corresponding matrix entries. The Frobenius norm is the square root of the sum of the squared entries.

Intuitively, alignment measures whether the patterns in the kernel matrix agree with the patterns suggested by the labels. Maximising alignment can be used as a training objective, although the precise objective and its normalisation vary across methods.

18.5.4 A small conceptual example

Suppose four examples have labels:

y = (+1, +1, −1, −1)

The target matrix has positive entries for pairs with matching labels and negative entries for pairs with different labels. A useful learned kernel would ideally assign higher similarities to examples from the same class and lower similarities to examples from different classes.

This is an intuition, not a universal rule that every pair of same-class points must have a larger kernel value than every pair of different-class points. Real datasets can overlap, contain noise and have complex class boundaries.

18.5.5 How is the kernel trained?

1

Choose a parameterised circuit

Select the number of qubits, encoding gates, trainable rotations and entangling operations. These choices determine the family of kernels the model can represent.

2

Estimate the kernel matrix

Prepare circuits for training pairs and estimate their fidelity values. The result depends on the current parameters θ.

3

Evaluate a training objective

Calculate kernel alignment or another suitable objective based on the labels and estimated kernel.

4

Update the circuit parameters

Use a classical optimiser and, when needed, gradient estimates to update θ. Repeat until the stopping criterion is reached.

This procedure creates a hybrid training loop. The quantum processor evaluates the parameter-dependent circuit, and the classical optimiser decides how to change the parameters.

18.5.6 Alignment is not the same as generalisation

A kernel can align closely with the training labels and still perform poorly on unseen data. If the kernel is tuned too aggressively to a small training set, it may capture accidental patterns rather than useful relationships.

Kernel training must therefore be evaluated using validation data that is kept separate from the training data. Hyperparameters should be selected without using the final test labels. A high alignment score is useful evidence about the training representation, but it is not proof of strong predictive performance.

Connection to Chapter 17: Variational quantum circuits also have trainable parameters, but their outputs and training objectives differ. A variational quantum model commonly learns from measured observables, whereas a trainable quantum kernel learns a similarity function that is subsequently used by a kernel-based classical learner.

18.6 Exponential Concentration and Kernel Pitfalls

18.6.1 Why can quantum similarities become uninformative?

A quantum state may have an enormous number of amplitudes, but this does not guarantee that its overlap with another state provides useful information. In some feature-map families, especially under particular choices of random circuits, increasing circuit depth or system size can cause pairwise fidelities to concentrate around a common value.

Imagine calculating similarities between hundreds of examples. If almost every pair receives approximately the same kernel value, the matrix no longer distinguishes meaningful relationships between examples. The SVM then receives little useful information about which examples are alike and which are different.

This phenomenon is called kernel concentration. Its severity depends on the circuit family, input distribution, circuit depth, measurement strategy and system size. It is not a universal property of every quantum kernel.

18.6.2 Concentration of fidelity

For two independent random pure states in a complex Hilbert space of dimension D, the expected squared overlap is:

E[|⟨ψ|φ⟩|²] = 1/D

If the states are distributed uniformly according to the Haar measure, the fidelity also has variance:

Var(|⟨ψ|φ⟩|²) = (D − 1) / [D²(D + 1)]

For n qubits, D = 2ⁿ. The expected overlap is therefore 2⁻ⁿ. As the number of qubits increases, the typical overlap becomes very small, and the absolute spread around its mean also becomes small.

This example explains why highly random quantum states can have pairwise fidelities that are difficult to distinguish accurately. However, real feature-map states are not necessarily independent Haar random states. The equations describe a particular random-state model, not every quantum learning circuit.

18.6.3 The connection to measurement cost

Suppose the kernel values of interest are extremely small. Estimating a probability near zero to a useful relative precision can require many shots. A circuit might therefore be difficult to use even when its mathematical kernel is well-defined.

Concentration can also create a learning problem: the matrix entries become similar to one another, so the classifier cannot easily use them to distinguish classes. The difficulty is not only that the quantum calculation is expensive. The resulting representation may itself be unsuitable for learning.

18.6.4 Barren plateaus and related training difficulties

A related but distinct issue occurs when training the parameters of a quantum circuit. In some parameterised circuits, the variance of gradients can decrease rapidly with system size. Such a region is commonly called a barren plateau.

If gradients are very small compared with their estimation noise, a classical optimiser may struggle to find a useful parameter update. This is particularly relevant when trainable kernels rely on deep or highly expressive circuits.

Kernel concentration and barren plateaus should not be confused. Concentration concerns the distribution of similarities between data points. A barren plateau concerns the difficulty of obtaining useful gradients for parameter optimisation. They can arise together in some settings, but one does not automatically imply the other.

18.6.5 Other practical pitfalls

1. Data encoding cost

Classical features must be loaded into the quantum circuit. If encoding requires many gates or repeated state preparations, the cost may remove any advantage.

2. Too many kernel entries

An m-example training set requires m² entries in the full Gram matrix. The number of distinct pairs still grows quadratically with m.

3. Hardware noise

Imperfect gates and measurements can distort similarities. Deep circuits often accumulate more errors.

4. Unfair baselines

A quantum kernel should be compared with tuned classical kernels, suitable feature engineering and comparable computational budgets.

5. Overfitting

A trainable kernel can learn accidental properties of the training set. Validation and independent testing remain necessary.

6. Classical simulation limits

Simulating a quantum circuit may become expensive as qubit count and circuit complexity grow. A small simulator result does not establish hardware advantage.

18.6.6 How should a quantum kernel be evaluated?

A careful experiment should evaluate both the statistical learning performance and the computational cost of the complete pipeline.

  • Compare against linear, polynomial and RBF kernels where appropriate.
  • Use the same train, validation and test splits for every method.
  • Report accuracy and suitable metrics such as precision, recall, F1 score or ROC-AUC.
  • Inspect the distribution of kernel entries and the spectrum of the Gram matrix.
  • Report the number of qubits, circuit depth, shots, execution time and hardware conditions.
  • Separate simulator results from results obtained on actual quantum hardware.
  • Include data encoding, kernel estimation, preprocessing and classical training in the cost comparison.
The scientific standard: A useful quantum kernel should do more than look mathematically sophisticated. It should preserve task-relevant information, remain estimable at a reasonable cost and generalise to unseen data.

18.7 Hands-on: Quantum Kernels with scikit-learn Integration

In this exercise, we will build a small binary classifier using a quantum fidelity kernel and a classical SVM. We will use Qiskit to construct the quantum circuit and scikit-learn to prepare the dataset, train the classifier and measure its performance.

The goal is to understand the complete workflow rather than to claim a quantum speed-up. A simulator is suitable for learning because it lets us inspect the kernel without needing access to quantum hardware.

18.7.1 Install the packages

Run the following command in a fresh Python environment. The example uses the current Qiskit circuit and simulator interfaces together with scikit-learn. Quantum package APIs change over time, so use compatible versions if your installed environment differs. 

python -m pip install qiskit qiskit-aer scikit-learn numpy

18.7.2 Design the feature map

We will use two qubits and two input features. Each feature controls a rotation gate. A controlled-Z gate then introduces an interaction between the qubits. Finally, the circuit applies another input-dependent rotation layer.

The entangling gate makes the circuit more expressive than two entirely independent single-qubit rotations. However, the presence of entanglement does not guarantee that the resulting kernel will classify the dataset well. 

import numpy as np

from qiskit import QuantumCircuit
from qiskit.quantum_info import Statevector
from sklearn.datasets import make_moons
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import MinMaxScaler
from sklearn.svm import SVC
from sklearn.metrics import accuracy_score, classification_report
from sklearn.metrics.pairwise import rbf_kernel


def feature_map(x):
    """
    Prepare a two-qubit quantum state from two real-valued features.

    The input is assumed to contain two scaled features.
    """
    qc = QuantumCircuit(2)

    # Encode the classical features.
    qc.ry(float(x[0]), 0)
    qc.ry(float(x[1]), 1)

    # Introduce an interaction between the qubits.
    qc.cz(0, 1)

    # Apply a second input-dependent layer.
    qc.ry(float(np.pi * x[0]), 0)
    qc.ry(float(np.pi * x[1]), 1)

    return qc

18.7.3 Understand the circuit

The first pair of rotations encodes the input into the qubits. The controlled-Z gate adds a phase that depends on the joint computational state of the two qubits. The final rotations mix the resulting amplitudes again.

Notice that this is a chosen example of a feature map, not a universally optimal circuit. Its performance depends on the dataset and the input scaling. We should test different designs rather than assume that additional gates will always improve the model.

18.7.4 Define the quantum fidelity kernel

For each pair of examples x and z, we construct the statevectors corresponding to their feature maps. The inner product is then calculated, and its squared magnitude gives the fidelity kernel.

Statevector simulation calculates the amplitudes directly. This is convenient for a tutorial, but it is not the same as estimating the overlap through repeated measurements on physical quantum hardware. 

def quantum_kernel_value(x, z):
    """
    Exact fidelity kernel using statevector simulation.

    This is a simulator-based calculation, not a hardware
    measurement experiment.
    """
    state_x = Statevector.from_instruction(feature_map(x))
    state_z = Statevector.from_instruction(feature_map(z))

    overlap = np.vdot(state_x.data, state_z.data)

    # Squared magnitude of the complex overlap.
    value = float(np.abs(overlap) ** 2)

    return value


def quantum_kernel_matrix(X1, X2):
    """
    Return the matrix K[i, j] = K(X1[i], X2[j]).
    """
    matrix = np.empty((len(X1), len(X2)), dtype=float)

    for i, x in enumerate(X1):
        for j, z in enumerate(X2):
            matrix[i, j] = quantum_kernel_value(x, z)

    return matrix

18.7.5 Prepare a nonlinear dataset

We will use the two-moons dataset. It contains two curved groups of points, making it a useful demonstration of nonlinear classification. The dataset is synthetic, so it is appropriate for experimentation without requiring an external data source. 

# Generate a reproducible two-class dataset.
X, y = make_moons(
    n_samples=120,
    noise=0.12,
    random_state=42
)

# Split before fitting the scaler to avoid data leakage.
X_train, X_test, y_train, y_test = train_test_split(
    X,
    y,
    test_size=0.25,
    random_state=42,
    stratify=y
)

# Fit scaling only on training data.
scaler = MinMaxScaler(feature_range=(0, np.pi))

X_train = scaler.fit_transform(X_train)
X_test = scaler.transform(X_test)

print("Training examples:", len(X_train))
print("Test examples:", len(X_test))
print("Features per example:", X_train.shape[1])

We scale the features into the interval from zero to π because the feature map uses them as rotation angles. Scaling is part of the model design: changing the scale changes the prepared quantum states and therefore changes the kernel.

18.7.6 Construct the kernel matrices

The training matrix contains similarities between training examples. The test matrix contains similarities between test examples and training examples. In scikit-learn, the custom-kernel interface expects the second matrix to have one row per test example and one column per training example. 

# Calculate the training Gram matrix.
K_train = quantum_kernel_matrix(X_train, X_train)

# Calculate similarities between test and training examples.
K_test = quantum_kernel_matrix(X_test, X_train)

print("Training kernel shape:", K_train.shape)
print("Test kernel shape:", K_test.shape)

# Basic checks for the ideal fidelity kernel.
print("Minimum training entry:", K_train.min())
print("Maximum training entry:", K_train.max())
print("Maximum symmetry error:",
      np.max(np.abs(K_train - K_train.T)))
print("Diagonal close to one:",
      np.allclose(np.diag(K_train), 1.0, atol=1e-8))

For this simulator-based example, the training kernel should be symmetric, with entries between zero and one and diagonal values close to one. These checks help identify implementation errors before model training.

18.7.7 Train a classical SVM using the quantum kernel

Scikit-learn's SVC accepts a precomputed kernel matrix. We pass the training Gram matrix during fitting and the test kernel matrix during prediction. 

# Train the SVM using the precomputed quantum kernel.
quantum_svm = SVC(
    kernel="precomputed",
    C=1.0
)

quantum_svm.fit(K_train, y_train)

# Predict test labels.
y_pred_quantum = quantum_svm.predict(K_test)

print(
    "Quantum-kernel SVM accuracy:",
    accuracy_score(y_test, y_pred_quantum)
)

print(
    classification_report(
        y_test,
        y_pred_quantum,
        zero_division=0
    )
)

This is the main integration point: scikit-learn does not need to understand quantum circuits. It only needs a valid kernel matrix. The quantum circuit supplies the similarities, while the SVM handles the classification optimisation.

18.7.8 Compare against a classical RBF kernel

A quantum-kernel experiment is incomplete without a baseline. The RBF kernel is a strong starting point for many nonlinear classification problems. We will tune its main hyperparameter using cross-validation on the training set, then evaluate the selected model on the same held-out test set. 

from sklearn.model_selection import GridSearchCV

# Tune the classical RBF kernel using training data only.
rbf_search = GridSearchCV(
    estimator=SVC(kernel="rbf"),
    param_grid={
        "C": [0.1, 1.0, 10.0, 100.0],
        "gamma": ["scale", 0.1, 1.0, 10.0]
    },
    cv=5,
    scoring="accuracy",
    n_jobs=-1
)

rbf_search.fit(X_train, y_train)

rbf_svm = rbf_search.best_estimator_
y_pred_rbf = rbf_svm.predict(X_test)

print("Best RBF parameters:", rbf_search.best_params_)
print(
    "Classical RBF accuracy:",
    accuracy_score(y_test, y_pred_rbf)
)

Compare the test scores, but do not draw a general conclusion from a single small dataset or random split. The RBF baseline has been tuned, whereas the example quantum feature map is fixed. For a more rigorous study, repeat experiments across several random seeds, tune both approaches fairly and report uncertainty in the results.

18.7.9 Optional: inspect the kernel values

We can inspect the distribution of the training kernel entries to understand whether the feature map creates a useful range of similarities. A matrix in which almost all off-diagonal entries are nearly identical may have limited discriminatory power. 

off_diagonal = K_train[
    ~np.eye(len(K_train), dtype=bool)
]

print("Off-diagonal mean:", off_diagonal.mean())
print("Off-diagonal standard deviation:",
      off_diagonal.std())
print("Smallest eigenvalue:",
      np.linalg.eigvalsh(
          (K_train + K_train.T) / 2
      ).min())

The eigenvalue check uses the symmetrised matrix to reduce the effect of tiny numerical asymmetries. For an exact fidelity kernel, the Gram matrix should be positive semidefinite, apart from small numerical errors. If the smallest eigenvalue is significantly negative, inspect the implementation and numerical precision before drawing conclusions.

18.7.10 What would change on real hardware?

The tutorial uses exact statevector simulation, so it does not include shot noise or hardware noise. On hardware, the overlap would usually be estimated by executing the circuit U(x)†U(z) repeatedly and measuring how often the all-zero outcome occurs.

That change introduces a practical challenge: every pairwise kernel value needs an estimate. For larger training sets, the number of circuit evaluations and shots can become expensive. Hardware experiments should therefore report the total number of circuit executions, shots, circuit depth and the backend used.

Hands-on conclusion: You have built a complete hybrid classification pipeline: classical data → quantum feature map → quantum kernel matrix → scikit-learn SVM → test evaluation. The same precomputed-kernel interface can be used with many other valid kernels.

Chapter Summary: Connecting the Ideas

Quantum kernel methods become easier to understand when viewed as a sequence of connected ideas rather than as a collection of unrelated equations.

1

Feature maps change the representation

Classical or quantum feature maps transform inputs into a space where useful patterns may be easier to learn.

2

Kernels compare transformed inputs

A kernel provides the inner product between representations, often without explicitly constructing the complete feature vectors.

3

Quantum circuits prepare the representations

An input-dependent unitary U(x) prepares a quantum state |φ(x)⟩. The fidelity kernel compares two such states using their squared overlap.

4

Measurements estimate similarities

The circuit U(x)†U(z) and repeated measurements estimate the all-zero probability. Repeated shots reduce sampling uncertainty.

5

The classical learner uses the kernel

A support vector machine uses the Gram matrix to learn a decision boundary. Quantum state preparation does not remove the need for classical optimisation.

6

Training and evaluation determine usefulness

Trainable kernels can adapt their representations, but concentration, sampling cost, hardware noise and overfitting must all be considered.

The most important equations

Classical kernel: K(x,z) = φ(x) · φ(z)
Quantum feature state: |φ(x)⟩ = U(x)|0⟩⊗n
Quantum fidelity kernel: K(x,z) = |⟨φ(x)|φ(z)⟩|²
Kernel estimation: K̂(x,z) = N0 / N
Quantum SVM: learn from K(xᵢ,xⱼ), rather than explicit quantum feature vectors

Final perspective

Quantum kernel methods offer a clear way to combine quantum circuits with established machine-learning algorithms. Their central idea is straightforward: encode each example into a quantum state, measure similarities between states, and use those similarities to train a classical learner.

The difficult part is choosing a representation that is both useful for the learning task and efficient to estimate. A larger state space is not enough. The kernel must distinguish relevant examples, the resulting classifier must generalise, and the full workflow must justify its computational cost.

That is the standard against which quantum kernel methods should be studied: not merely whether quantum mechanics creates a different representation, but whether that representation provides a measurable and reproducible advantage for a real learning problem.
