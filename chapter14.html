Introduction: What Does It Mean for a Machine to Learn?

Imagine that we want to build a program that identifies whether an email is spam. One approach is to write hundreds of rules: mark an email as suspicious if it contains certain words, too many links, unusual formatting, or a suspicious sender address. Such rules can work, but spammers constantly change their methods. Maintaining all the rules becomes difficult.

Machine learning offers another approach. Instead of telling the computer every rule, we provide examples of spam and genuine emails. A learning algorithm examines these examples and builds a model that can recognise patterns. When a new email arrives, the model uses what it has learnt to predict whether the email is spam.

The word model refers to the mathematical object that makes predictions. The algorithm is the procedure used to construct or improve that model. The data supplies the evidence from which learning takes place.

A familiar example: Suppose a child sees photographs of many cats and dogs. Over time, the child learns to notice useful differences, such as facial shape, ears and body structure. A machine learning system attempts something similar using numerical representations of images and a mathematical learning process.

14.0.1 The Basic Mathematical Idea

A dataset contains examples. Each example has an input, often represented by a vector of numbers, and may have a desired output. We write an input as x and its target output as y. The model, with adjustable parameters represented by θ, makes a prediction.

Prediction: ŷ = fθ(x)

Here, f represents the model, θ represents its adjustable parameters, x represents the input and ŷ represents the predicted output. The goal is to choose useful parameter values so that the predictions are accurate on data the model has not seen before.

This process creates a pattern that connects nearly every topic in this chapter:

Step 1 — Data: Collect examples that describe the problem.
Step 2 — Model: Choose a mathematical structure capable of making predictions.
Step 3 — Loss: Measure how far the predictions are from the desired results.
Step 4 — Optimisation: Adjust the model parameters to reduce the loss.
Step 5 — Evaluation: Check whether the model works on new examples.

These steps form the foundation of supervised learning and many modern neural network systems. Other learning paradigms change how feedback is obtained, while retaining several of the same ideas.

14.1 Supervised, Unsupervised, and Reinforcement Learning

Machine learning problems differ partly in the kind of information available during learning. Sometimes we know the correct answer for every training example. Sometimes we only have raw data and must discover its structure. In other cases, an agent takes actions and receives rewards or penalties.

14.1.1 Supervised Learning

In supervised learning, the training dataset contains inputs and their corresponding target outputs. The model learns a relationship between them.

A training dataset can be represented as a collection of input-output pairs:

D = {(x₁, y₁), (x₂, y₂), ..., (xₙ, yₙ)}

The model predicts an output for each input, compares the prediction with the target and uses the difference to improve its parameters.

Supervised learning is commonly divided into two major types: classification and regression.

Classification

Classification predicts a category. The answer might be spam or not spam, cat or dog, fraudulent or genuine, or one of several possible medical image categories.

A binary classifier predicts one of two classes. A multiclass classifier predicts one class from three or more possibilities. Some applications require multilabel classification, in which one example can belong to several categories simultaneously.

Example: A model receives the numerical features of a bank transaction and predicts whether the transaction is fraudulent. The output might be a probability such as 0.92 for the fraud class. A decision threshold is then used to convert that probability into an operational decision.

Regression

Regression predicts a numerical quantity rather than a category. Examples include predicting house prices, electricity demand, delivery time or tomorrow's temperature.

A regression model might learn that house prices depend on location, area, age and other features. Its output is a numerical estimate, such as ₹65 lakh.

Remember: Classification predicts a class; regression predicts a numerical value. Both can be learnt from labelled examples.

14.1.2 Unsupervised Learning

In unsupervised learning, we usually have inputs without target labels. The algorithm tries to discover useful structure in the data instead of learning from a supplied correct answer for every example.

Clustering

Clustering groups examples according to their similarities. A company might group customers by purchasing behaviour without having predefined customer categories.

K-means is a popular clustering algorithm. It starts with a chosen number of cluster centres, assigns each example to a nearby centre, recalculates the centres and repeats these steps until the assignments or centres stabilise.

Its objective is to minimise the total squared distance between each data point and the centre of its assigned cluster.

J = Σᵢ ||xᵢ − μcᵢ||²

Here, xᵢ is a data point, cᵢ is its assigned cluster and μcᵢ is that cluster's centre. The number of clusters must generally be chosen or estimated beforehand.

Dimensionality Reduction

A dataset may contain hundreds or thousands of features. Some features may be redundant, correlated or less useful for the task. Dimensionality reduction represents the data using fewer variables while attempting to preserve important information.

Principal Component Analysis (PCA) finds directions that capture large amounts of variation in numerical data. It is useful for exploration, compression and visualisation, although directions with high variance are not necessarily the directions most useful for prediction.

Representation Learning

Some unsupervised and self-supervised methods learn representations that capture meaningful structure in data. For example, a model might learn that different photographs of the same object share important visual features even when their backgrounds are different.

These representations can later be used for classification, search, recommendation or other downstream tasks.

14.1.3 Reinforcement Learning

Reinforcement learning studies how an agent learns to make decisions by interacting with an environment. Instead of receiving the correct action for every situation, the agent receives feedback in the form of rewards or penalties.

Consider a game-playing agent. It observes the current situation, chooses a move, receives a reward or penalty and observes the new situation. Across many interactions, it attempts to learn a strategy that produces high total reward.

The main components are:

  • Agent: The decision-making system.
  • Environment: The world in which the agent acts.
  • State: The information describing the current situation.
  • Action: A choice available to the agent.
  • Reward: Numerical feedback describing the immediate outcome.
  • Policy: The strategy used to choose actions.

The objective is often to maximise expected discounted return:

Gₜ = Rₜ₊₁ + γRₜ₊₂ + γ²Rₜ₊₃ + ...

Here, R represents future rewards, and γ is the discount factor between zero and one. A smaller γ places relatively more importance on immediate rewards, while a value closer to one gives more weight to distant rewards.

The agent must often balance exploration, which means trying unfamiliar actions to learn about them, and exploitation, which means choosing actions already believed to be good.

14.1.4 Comparing the Three Paradigms

Learning type Feedback available Main goal Example
Supervised Target labels or values Predict the correct output Spam detection
Unsupervised No supplied target labels in the basic setting Discover structure Customer clustering
Reinforcement Rewards from actions and outcomes Learn a good decision-making policy Game-playing agent

These categories are not exhaustive or completely separate. Self-supervised learning creates training targets from the data itself, while semi-supervised learning combines labelled and unlabelled examples. Modern systems may combine several learning approaches in one pipeline.

14.2 Loss Functions and Optimisation

Once we choose a model, we need a way to determine whether it is making good predictions. This is the job of a loss function. It converts a prediction error into a numerical value that the training process can attempt to reduce.

Imagine that a model predicts the price of a house as ₹50 lakh when the actual price is ₹60 lakh. The prediction is wrong by ₹10 lakh. A loss function gives us a numerical measure of that mistake.

Different problems require different loss functions because different mistakes have different meanings.

14.2.1 Mean Squared Error

Mean Squared Error (MSE) is commonly used in regression. It calculates the average squared difference between predicted values and actual values.

MSE = (1/n) Σᵢ (yᵢ − ŷᵢ)²

Here, yᵢ is the actual value, ŷᵢ is the predicted value and n is the number of examples.

Squaring ensures that positive and negative errors do not cancel each other out. It also penalises large errors more heavily than small ones.

Example: Suppose the actual values are 10 and 20, while the predictions are 12 and 17. The squared errors are 4 and 9. The MSE is (4 + 9) / 2 = 6.5.

MSE is useful when large errors deserve extra attention. However, a single extreme outlier can dominate the loss. Mean Absolute Error, or MAE, instead averages the absolute errors and is less sensitive to extreme errors.

MAE = (1/n) Σᵢ |yᵢ − ŷᵢ|

14.2.2 Binary Cross-Entropy

For binary classification, a model often predicts the probability that an example belongs to the positive class. If the target is either zero or one, binary cross-entropy measures how well the predicted probability agrees with that target.

L = −[y log(p) + (1 − y) log(1 − p)]

Here, y is the true label and p is the predicted probability of the positive class. When the true label is one, predicting a probability close to one gives a small loss. Predicting a probability close to zero gives a very large loss. The reverse applies when the true label is zero.

This makes cross-entropy useful for teaching a classifier not only to choose the right class, but also to assign sensible probabilities to its predictions.

14.2.3 Multiclass Cross-Entropy

For a problem with several mutually exclusive classes, a model may produce one probability for each class. A softmax function is commonly used to turn a set of scores, called logits, into probabilities.

P(y = k | x) = eᶻᵏ / Σⱼ eᶻʲ

Here, zₖ is the score for class k. The denominator sums the exponentials of the scores for all classes, so the resulting probabilities add up to one.

Multiclass cross-entropy then penalises the model when it assigns a low probability to the correct class.

14.2.4 The Difference Between Loss and Evaluation Metrics

A loss function is usually selected to support training. An evaluation metric describes performance in terms that are useful for understanding the actual task. The two may be related, but they do not have to be the same.

For example, a spam classifier may be trained using cross-entropy but evaluated using precision, recall and the F1-score. These metrics help explain how many spam emails were detected and how many genuine emails were mistakenly marked as spam.

14.2.5 What Is Optimisation?

A model has parameters that affect its predictions. Optimisation is the process of finding parameter values that minimise an objective function, often the average training loss plus any regularisation terms.

θ* = arg minθ L(θ)

This notation means that we seek parameter values θ* that make the loss L as small as possible.

A simple model may have only a few parameters. A large neural network may have millions or billions. Finding good parameters in such a large space is a major computational challenge.

Key idea: The loss function tells the learning algorithm what it should improve. Optimisation determines how the model parameters are changed to achieve that improvement.

14.3 Gradient Descent and Backpropagation

Suppose we are standing on a hill covered in fog and want to reach a low point. We cannot see the whole landscape, but we can estimate which direction slopes downward near our current position. We take a small step downhill, examine the new position and repeat.

Gradient descent follows a similar idea. The hill represents the loss function, and our position represents the current model parameters. We repeatedly update the parameters in a direction that is expected to reduce the loss.

14.3.1 Understanding the Gradient

A derivative describes how a function changes when its input changes. If a small increase in a parameter causes the loss to increase, the derivative is positive. If it causes the loss to decrease, the derivative is negative.

For a model with many parameters, we collect the partial derivatives into a gradient vector. It describes how the loss changes with respect to each parameter.

∇L(θ) = [∂L/∂θ₁, ∂L/∂θ₂, ..., ∂L/∂θₘ]

The gradient points in the direction of the steepest local increase in a differentiable function. To reduce the loss, gradient descent moves in the opposite direction.

14.3.2 The Gradient Descent Update Rule

θt+1 = θt − η∇L(θt)

The parameter θ at step t is updated using the gradient of the loss. The symbol η, called the learning rate, controls the size of the update.

  • A very small learning rate may make training extremely slow.
  • A very large learning rate may cause the loss to jump around or diverge.
  • A suitable learning rate can make training faster and more stable.

Consider a simple example in which the loss is L(w) = w². Its derivative is 2w. If the current parameter is w = 4 and the learning rate is 0.1, the next value is:

wnew = 4 − 0.1(2 × 4) = 3.2

The parameter has moved closer to zero, where this particular loss reaches its minimum. Real machine learning problems are usually much more complicated, but the underlying update principle is similar.

14.3.3 Batch, Stochastic and Mini-Batch Gradient Descent

A training dataset may contain millions of examples. Calculating the gradient using every example for every update can be expensive. There are several ways to decide which examples contribute to an update.

Method Examples used per update Characteristics
Batch gradient descent The entire training dataset Uses the full dataset gradient, but each update can be expensive.
Stochastic gradient descent One example Frequent, noisy updates with low per-update cost.
Mini-batch gradient descent A small group of examples Balances computational efficiency and gradient stability.

Mini-batch training is widely used for neural networks. A batch of examples is processed together, and its average loss is used to calculate an approximate gradient. Modern hardware can process batches efficiently in parallel.

14.3.4 What Is Backpropagation?

Gradient descent explains how parameters are updated. However, a neural network may contain millions of parameters arranged across many connected layers. We need an efficient way to calculate the gradient of the loss with respect to all these parameters.

Backpropagation is the algorithm that efficiently computes these gradients by applying the chain rule of calculus through the network, starting from the loss and moving backwards through the computations.

A neural network first performs a forward pass. It takes the input, calculates the output and measures the loss. During backpropagation, it works backwards to determine how each intermediate value and parameter contributed to that loss.

Forward pass: Input → layers → prediction → loss.
Backward pass: Loss gradient → output layer → earlier layers → parameter gradients.
Parameter update: An optimiser uses the calculated gradients to change the weights and biases.

14.3.5 The Chain Rule

The chain rule explains how the derivative of a composition of functions can be calculated from the derivatives of its parts. If one quantity depends on another, which in turn depends on a third, their derivatives can be combined to calculate the overall rate of change.

If z = f(y) and y = g(x), then dz/dx = (dz/dy)(dy/dx)

A neural network is a composition of many functions. Applying the chain rule repeatedly allows the loss gradient to travel backwards through the layers.

For a simple neuron, let z = wx + b and let the activation be a = σ(z). If the loss is L(a), the chain rule gives:

∂L/∂w = (∂L/∂a)(∂a/∂z)(∂z/∂w)

Since ∂z/∂w = x, the gradient with respect to the weight depends on the input, the activation's derivative and the loss gradient at the output.

14.3.6 Backpropagation Is Not the Same as Gradient Descent

These two concepts are often mentioned together, but they have different jobs. Backpropagation calculates gradients. Gradient descent uses those gradients to update parameters. They form two parts of the training process.

The optimiser need not be basic gradient descent. Adam, RMSProp and momentum-based methods use additional information from current or previous gradients to influence updates. Adam, for example, maintains moving estimates of the gradients and their squared values.

Important distinction: Backpropagation does not independently teach the network or choose its final parameters. It calculates how the loss changes with the parameters. Learning emerges from repeatedly combining gradient calculation, parameter updates and feedback from training examples.

14.4 Overfitting, Regularisation and Generalisation

A model can perform extremely well on its training data and still fail when presented with new examples. This is one of the most important problems in machine learning. To understand why it happens, we must distinguish between memorising examples and learning useful patterns.

14.4.1 Training, Validation and Test Data

A dataset is commonly divided into separate portions for different purposes.

  • Training set: Used to fit the model parameters.
  • Validation set: Used to compare models, tune hyperparameters and decide when to stop training.
  • Test set: Used for a final, relatively unbiased assessment after the development decisions are complete.

A hyperparameter is a setting chosen outside the ordinary parameter-learning process. Examples include learning rate, tree depth, batch size, number of layers and regularisation strength.

The test set should not be repeatedly used to make design decisions. If we keep adjusting the model based on its test results, we gradually adapt to the test set itself, weakening its role as an independent assessment.

14.4.2 Underfitting

Underfitting occurs when a model is too limited, is not trained sufficiently or otherwise fails to capture the important patterns in the data. It usually performs poorly on both training data and unseen data.

For example, a straight line may be unable to describe a strongly curved relationship between a house's size and its price. The problem is not necessarily a lack of data; the model may simply be too restrictive.

14.4.3 Overfitting

Overfitting occurs when a model learns details of the training examples that do not reliably carry over to new examples. These details may include noise, accidental correlations and unusual cases.

Imagine a student who memorises the answers to a set of practice questions without understanding the underlying concepts. The student may score full marks on those exact questions but struggle when the examiner changes their wording. An overfitted model behaves in a similar way.

Example: A model trained on photographs of dogs may accidentally learn to associate grass with the dog class because most training photographs contain grass. When it sees a dog indoors, it may make a mistake. It has learnt a misleading shortcut rather than a robust representation of dogs.

14.4.4 Generalisation

Generalisation is the ability of a trained model to perform well on examples drawn from the intended population that were not used to fit the model. Good generalisation is the real objective of most predictive machine learning.

A model that generalises well has learnt patterns that remain useful beyond the exact examples it saw during training. This does not mean it must perform perfectly on every new input. Its performance depends on the data distribution, model design, training procedure and evaluation conditions.

14.4.5 The Bias-Variance Trade-off

Bias and variance describe two different sources of prediction error in many statistical learning settings. High bias is associated with models that are too restrictive to capture the real pattern. High variance is associated with models whose learned behaviour changes substantially when the training data changes.

A very simple model may have high bias. A very flexible model trained on limited or noisy data may have high variance. Model selection often involves balancing these tendencies.

Under the assumptions of the classical squared-error decomposition, expected prediction error can be expressed in terms of squared bias, variance and irreducible noise. The exact decomposition depends on the setting and the evaluation point.

Expected squared error = Bias² + Variance + Irreducible noise

14.4.6 Regularisation

Regularisation discourages models from becoming unnecessarily complex or from relying too heavily on certain parameters. It adds constraints or penalties to the learning process.

L2 Regularisation

L2 regularisation adds a penalty proportional to the sum of squared parameter values. In many settings, this encourages smaller weights and smoother behaviour.

Ltotal = Ldata + λΣᵢ θᵢ²

The coefficient λ controls the strength of the penalty. If it is too small, it may have little effect. If it is too large, the model may become too restricted and underfit the data.

L1 Regularisation

L1 regularisation penalises the sum of the absolute parameter values. It can encourage some weights to become exactly zero, which may produce sparse models.

Ltotal = Ldata + λΣᵢ |θᵢ|

Other Ways to Reduce Overfitting

  • More representative data: Helps the model encounter a wider range of genuine situations.
  • Data augmentation: Creates valid variations of training examples, such as cropping images or changing their orientation where appropriate.
  • Dropout: Randomly disables selected neural network activations during training to discourage excessive dependence on particular pathways.
  • Early stopping: Stops training when validation performance no longer improves as expected.
  • Model simplification: Reduces the model's capacity when the existing model is unnecessarily complex.
  • Cross-validation: Repeats training and validation across different data splits to assess how sensitive performance is to the split.
Data leakage warning: Information from validation or test data must not accidentally enter training in a way that makes evaluation unrealistically easy. For example, normalising all the data before splitting it can leak information about the test distribution. Fit preprocessing steps on the training data, then apply the fitted transformations to validation and test data.

14.4.7 Distribution Shift

A model may generalise well to a test set but perform poorly after deployment because the real-world data distribution has changed. This is known as distribution shift. Examples include changing customer behaviour, new types of fraud, changes in camera quality or a population whose characteristics differ from the training population.

Therefore, generalisation is not guaranteed merely because a model scores well on one test set. Reliable deployment also requires representative evaluation, monitoring and periodic reassessment.

14.5 Kernel Methods and Support Vector Machines

Not every useful machine learning model needs to be a neural network. Kernel methods and support vector machines provide powerful ways to learn patterns, particularly when the data has a suitable structure and the dataset is not too large for the chosen method.

14.5.1 The Challenge of Non-Linear Data

Suppose we plot two classes of points on a graph. A linear classifier attempts to separate the classes using a straight line in two dimensions, or a hyperplane in higher dimensions. If the classes cannot be separated well by a straight boundary, a linear model may perform poorly.

A more flexible decision boundary may be needed. One possibility is to transform the input features so that a linear boundary in the transformed space corresponds to a non-linear boundary in the original space.

14.5.2 Feature Maps

A feature map, written as φ(x), transforms an input x into a representation containing features that may be more useful for separating classes.

Consider a two-dimensional input x = (x₁, x₂). We could add a feature based on the squared distance from the origin, such as x₁² + x₂². This extra feature can make circular patterns easier to separate using a linear boundary in the transformed feature space.

The difficulty is that an explicit feature map may produce an enormous number of features, or even an infinite-dimensional representation. Kernel methods provide a way to work with certain feature-space relationships without explicitly calculating every transformed feature.

14.5.3 The Kernel Trick

A kernel function calculates an inner product between feature representations directly from the original inputs. In a suitable feature space, a kernel can be written as:

K(x, z) = φ(x) · φ(z)

Instead of constructing φ(x) and φ(z) explicitly, the algorithm calculates K(x, z). This can make certain non-linear learning problems computationally practical.

Common Kernel Functions

Kernel Expression General behaviour
Linear K(x, z) = x · z Uses the original linear feature relationship.
Polynomial K(x, z) = (γx · z + r)d Represents interactions up to a degree controlled by d, under the relevant parameter settings.
RBF / Gaussian K(x, z) = exp(−γ||x − z||²) Measures similarity that decreases with squared distance.

In these expressions, γ and r are parameters, and d is the polynomial degree. For the RBF kernel, larger γ makes the similarity fall off more quickly with distance. Feature scaling and hyperparameter selection can strongly affect performance.

14.5.4 Support Vector Machines

A Support Vector Machine (SVM) is a supervised learning method often used for classification and, in a related formulation, regression. The basic SVM classifier attempts to find a decision boundary that separates the classes with a large margin.

The margin is the distance between the boundary and the closest training points from either class. These closest points are called support vectors. They play a central role in determining the decision boundary.

For a linearly separable dataset, a hard-margin SVM seeks a hyperplane that separates all training examples while maximising the margin. Real datasets often contain noise or overlapping classes, so a soft-margin SVM allows some violations of the margin constraints.

Minimise: (1/2)||w||² + CΣᵢ ξᵢ

This is a simplified expression of the soft-margin objective, with constraints omitted for readability. The vector w defines the separating hyperplane, ξᵢ measures margin violations and C controls the trade-off between a wide margin and training violations.

A small C permits more violations in exchange for a potentially wider margin. A large C penalises violations more strongly. The appropriate setting depends on the data.

14.5.5 When Are Kernel Methods Useful?

  • When the dataset is small or medium-sized and a strong traditional baseline is needed.
  • When the relationship between features and labels is non-linear.
  • When the number of features is high but the training set remains manageable.
  • When a well-understood mathematical objective and a controlled model are useful.

Kernel methods can become expensive for large datasets because many algorithms require calculations involving pairs of training examples. Neural networks are often preferred for very large image, audio and text tasks, where learned representations can be extremely useful. The best choice depends on the problem, data and computational budget.

14.6 Neural Networks and Deep Learning

Neural networks are flexible models built from connected computational units. They are loosely inspired by some ideas about biological nervous systems, but artificial neurons are mathematical operations rather than realistic models of biological neurons.

Their strength comes from combining many simple operations into a system that can learn complicated relationships from data. A network can begin with raw or lightly processed inputs and gradually construct representations that are useful for its task.

14.6.1 The Artificial Neuron

An artificial neuron receives input values, multiplies them by weights, adds a bias and passes the result through an activation function.

z = w₁x₁ + w₂x₂ + ... + wₙxₙ + b
a = σ(z)

The inputs x represent features. The weights w determine how strongly those features influence the neuron, while the bias b shifts its response. The activation function σ introduces non-linearity in many neural network designs.

14.6.2 Why Do We Need Activation Functions?

Suppose we stack many linear layers without any non-linear activation between them. The combined transformation is still equivalent to a single linear transformation. Merely adding more such layers would not provide the expressive power expected from a deep network.

Non-linear activation functions allow neural networks to represent much more complicated relationships.

ReLU

ReLU(x) = max(0, x)

ReLU returns zero for negative inputs and returns the input itself for positive inputs. It is simple and widely used in hidden layers, though it can cause some neurons to stop responding to typical inputs during training.

Sigmoid

σ(x) = 1 / (1 + e−x)

Sigmoid maps real numbers to values between zero and one. It is useful when an output needs to represent a binary probability, although it is less commonly used in the hidden layers of modern deep networks.

Tanh

tanh(x) = (eˣ − e−x) / (eˣ + e−x)

Tanh maps inputs to values between negative one and one. It is zero-centred, but like sigmoid it can suffer from small gradients for very large positive or negative inputs.

14.6.3 Layers and Network Architecture

A basic feedforward neural network contains an input layer, one or more hidden layers and an output layer. Information passes forward through the network to produce a prediction.

  • Input layer: Receives the representation of the example.
  • Hidden layers: Transform the representation into increasingly useful features.
  • Output layer: Produces a prediction in the form required by the task.

A hidden layer can be described mathematically as:

h = σ(Wx + b)

W is a matrix of weights, b is a bias vector and σ is applied to the layer's pre-activation values. Stacking such transformations creates a deep neural network.

14.6.4 What Makes Deep Learning Different?

Deep learning uses neural networks with multiple layers to learn representations at different levels of abstraction. The precise representations depend on the architecture and training objective, but a useful intuition comes from image recognition.

Early layers may respond to simple visual patterns such as edges and colour changes. Intermediate layers may combine these patterns into shapes or textures. Later layers may represent more complex object parts and combinations of features.

This is an illustration rather than a strict rule for every network. What matters is that the network can learn useful features from examples instead of requiring a human to design every feature manually.

14.6.5 Convolutional Neural Networks

Convolutional Neural Networks (CNNs) are designed to exploit spatial structure, especially in images. Instead of connecting every input pixel independently to every neuron in a large layer, convolutional layers apply small learned filters across local regions of an image.

The same filter is reused across different positions. This weight sharing reduces the number of parameters compared with many fully connected alternatives and allows the network to detect patterns in different parts of the image.

Pooling or strided convolutions can reduce the spatial dimensions of feature maps. Modern CNN designs use different combinations of convolutions, normalisation, activation functions and residual connections.

14.6.6 Recurrent Neural Networks

Recurrent Neural Networks (RNNs) process sequences by maintaining a hidden state that carries information from earlier steps. This makes them suitable for sequential data such as text, sensor readings and time series.

Traditional RNNs can struggle to preserve information over long sequences because gradients may vanish or grow excessively during backpropagation through time. Long Short-Term Memory networks (LSTMs) and Gated Recurrent Units (GRUs) introduce gates to control how information is retained and updated.

14.6.7 Transformers

Transformers process sequences using attention mechanisms that allow elements to exchange information based on their relevance to one another. Unlike a traditional recurrent network, a standard transformer can process many sequence positions in parallel during training, although attention computation has its own cost.

Consider the sentence, "The child placed the book on the table because it was heavy." To interpret the word "it", a model needs to consider the surrounding context. Attention provides a way for a token's representation to incorporate information from other tokens.

In scaled dot-product attention, queries, keys and values are learned projections of the input representations. Queries are compared with keys to calculate attention weights, and those weights determine how values are combined.

Attention(Q, K, V) = softmax(QKᵀ / √dₖ)V

Here, Q contains queries, K contains keys, V contains values and dₖ is the dimension of each key vector. Dividing by the square root of dₖ helps control the scale of the attention scores before softmax is applied.

Transformers commonly combine attention, feedforward networks, residual connections and normalisation. Positional information is also needed so that the model can represent sequence order.

14.6.8 The Complete Neural Network Training Cycle

1. Initialise: Set initial weights and biases, commonly using a suitable random initialisation scheme.
2. Forward pass: Calculate predictions from the current parameters.
3. Calculate loss: Compare the predictions with the training targets.
4. Backpropagate: Calculate gradients of the loss with respect to the parameters.
5. Optimise: Update the parameters using an optimiser such as SGD or Adam.
6. Repeat: Process further mini-batches over multiple epochs.
7. Validate: Monitor performance on separate validation data and adjust the training strategy where needed.

One epoch means that the training process has gone through the entire training dataset once, assuming the training procedure processes all of it. Several epochs may be required before the model learns useful patterns.

Deep learning has become powerful because of the combination of large datasets, efficient hardware, improved optimisation methods, suitable architectures and years of research. It is not simply a matter of making a network deeper.

14.7 Generative Models: GANs, VAEs, Diffusion and Transformers

Many machine learning models are designed to predict a label or a numerical value. Generative models have a different goal: they learn patterns in data well enough to produce new examples that resemble the data on which they were trained.

A generative model might produce a photograph, a paragraph, a piece of music, a molecular structure or a synthetic dataset. The output is newly generated, but its statistical structure is influenced by the patterns learnt from the training data and the model's objective.

14.7.1 What Does It Mean to Learn a Distribution?

A probability distribution describes how likely different possible outcomes are. A generative model attempts to capture useful aspects of the distribution of training data and then generate samples from its learned model.

For example, a model trained on handwritten digits learns statistical patterns of digit shapes. When asked to generate a new digit, it produces an image that resembles a digit without necessarily copying any single training image.

A conditional generative model can also use extra information, such as a text prompt, a class label or an input image, to guide the generated output.

14.7.2 Generative Adversarial Networks (GANs)

A Generative Adversarial Network contains two neural networks with competing objectives: a generator and a discriminator.

The Generator

The generator takes a random latent vector, often sampled from a simple distribution, and transforms it into a synthetic example. For an image GAN, the output is an image intended to resemble the training images.

The Discriminator

The discriminator receives real and generated examples and learns to distinguish between them. It provides feedback that helps the generator improve its outputs.

The generator tries to create convincing examples, while the discriminator tries to detect generated examples. Training is adversarial because the two networks have competing objectives.

minG maxD V(D,G) = Ex∼p data[log D(x)] + Ez∼p z[log(1 − D(G(z)))]

This is the original minimax objective for a basic GAN. D(x) is the discriminator's estimate that x is real, G(z) is a generated sample and the expectations average over real examples and latent inputs.

In practice, GAN training can be difficult. The generator and discriminator must improve in a reasonably balanced manner. One failure mode, called mode collapse, occurs when the generator produces only a limited variety of outputs instead of representing the diversity of the training distribution.

14.7.3 Variational Autoencoders (VAEs)

A Variational Autoencoder learns to represent data in a latent space and then reconstruct or generate examples from that space. It consists of an encoder and a decoder.

The encoder maps an input to a probability distribution over latent representations. In a common VAE, the encoder predicts the mean and variance of a Gaussian distribution. A latent vector is sampled from this distribution and passed to the decoder.

The decoder uses the latent vector to reconstruct the input or generate a new example. The model is trained using an objective that balances reconstruction quality with a regularisation term.

LVAE = Reconstruction loss + β KL(q(z|x) || p(z))

The reconstruction loss measures how well the output represents the input. The Kullback-Leibler divergence, written KL, measures how different the encoder's latent distribution is from a chosen prior distribution p(z). The coefficient β controls the strength of this term in this common form of the objective.

The prior encourages latent representations to have a useful structure from which new samples can be generated. VAEs are often associated with smooth latent spaces, though the quality and properties of generated samples depend on the architecture and training objective.

14.7.4 Diffusion Models

Diffusion models generate data by learning to reverse a gradual corruption process. The training process begins with real data and progressively adds noise. A neural network learns to predict or remove that noise at different noise levels.

During generation, the process starts from random noise and repeatedly applies learned denoising steps. After many steps, the result can become an image or another type of sample with meaningful structure.

Forward process: Start with a training image and gradually add noise until much of its original structure is obscured.
Training: Teach the model to predict the noise or an equivalent quantity from noisy examples at different steps.
Reverse process: Begin with random noise and use the trained model repeatedly to produce a structured sample.

A common mathematical description of the forward process is:

xₜ = √α̅ₜ x₀ + √(1 − α̅ₜ) ε

Here, x₀ is the original sample, ε is Gaussian noise, and α̅ₜ describes how much of the original signal remains at step t under a chosen noise schedule. As the process advances, the signal contribution generally decreases and the noise contribution increases.

Text-to-image diffusion systems can use a text encoder or other conditioning mechanism to guide denoising towards an image that matches a prompt. Diffusion models are powerful, but generation may require multiple network evaluations, making speed and computational cost important engineering considerations.

14.7.5 Transformers as Generative Models

Transformers are an architecture, not a single learning objective. They can be used for classification, translation, representation learning and many other tasks. Autoregressive transformers are especially important for text generation.

An autoregressive model predicts the next token using the tokens that came before it. A token may be a whole word, part of a word, punctuation or another unit determined by the tokenizer.

P(x₁, ..., xₙ) = Πᵢ P(xᵢ | x₁, ..., xᵢ₋₁)

This equation expresses a sequence probability as a product of conditional next-token probabilities. The model predicts one token, adds it to the context and predicts the next token. Repeating the process produces a sequence.

During training, the model is commonly shown sequences and trained to predict their next tokens. During inference, it uses its learned probability distribution to generate tokens one after another. Sampling methods or selection rules influence which token is chosen at each step.

Modern language models may be trained through multiple stages. Pretraining learns broad statistical patterns from large datasets. Additional fine-tuning or alignment procedures may encourage useful responses, instruction following or task-specific behaviour.

14.7.6 Comparing the Generative Approaches

Model family Core idea Strengths Challenges
GAN Generator competes with discriminator Can produce sharp, realistic samples Training instability and mode collapse
VAE Learn a latent distribution and reconstruct data Structured latent representations and principled probabilistic training Some variants produce less sharp samples
Diffusion Learn to reverse gradual corruption High-quality and diverse generation in many domains Generation can require many iterative steps
Autoregressive transformer Predict the next token or sequence element Strong sequence modelling and flexible conditioning Sequential generation cost and context limitations

These categories are not mutually exclusive. Transformers can be components of diffusion systems, and generative models can combine ideas from several families. The important difference is the learning and generation procedure, not simply the kind of output produced.

14.7.7 Generative Models and Their Limitations

A convincing generated sample is not necessarily factually correct, safe or useful. A language model can produce a fluent but false statement. An image model can generate plausible visual details that do not correspond to reality. Generated data may also reflect biases or unwanted patterns present in training data.

Generative models therefore require evaluation suited to their use case. Image quality, text usefulness, factual accuracy, diversity, privacy, safety and computational cost may all matter. No single metric captures every aspect of quality.

14.8 Evaluation Metrics and Benchmarking

Training loss alone cannot tell us whether a model is useful. We need evaluation methods that measure performance on data that was not used to fit the model, and the metrics must reflect the problem we are trying to solve.

14.8.1 Accuracy

Accuracy is the fraction of predictions that are correct. If a classifier makes 90 correct predictions out of 100 examples, its accuracy is 90%.

Accuracy = Correct predictions / Total predictions

Accuracy is easy to understand, but it can be misleading when the classes are imbalanced.

Example: Suppose only 1% of transactions are fraudulent. A model that labels every transaction as genuine achieves 99% accuracy, yet detects no fraud. The accuracy looks impressive, but the model fails at the most important part of the task.

14.8.2 Confusion Matrix

For binary classification, a confusion matrix compares predicted classes with actual classes.

Actual / Predicted Predicted positive Predicted negative
Actually positive True Positive (TP) False Negative (FN)
Actually negative False Positive (FP) True Negative (TN)

A true positive is a positive example correctly detected. A false positive is a negative example incorrectly labelled positive. A false negative is a positive example missed by the model, and a true negative is a negative example correctly identified.

14.8.3 Precision and Recall

Precision answers: among the examples predicted to be positive, how many were actually positive?

Precision = TP / (TP + FP)

Recall answers: among all actual positive examples, how many did the model successfully identify?

Recall = TP / (TP + FN)

Precision matters when false alarms are costly. Recall matters when missing positive cases is costly. Fraud detection, disease screening and spam filtering may require different balances between these two measures.

14.8.4 F1-Score

The F1-score is the harmonic mean of precision and recall. It becomes high only when both measures are reasonably high.

F1 = 2 × (Precision × Recall) / (Precision + Recall)

F1 is useful when both false positives and false negatives matter, but it does not include true negatives in its formula. It also treats precision and recall symmetrically. Other measures or explicit cost calculations may be more appropriate when one type of error is substantially more expensive than the other.

14.8.5 ROC-AUC and Precision-Recall Curves

A classifier that produces probabilities or scores can be evaluated at different decision thresholds. Raising the threshold generally reduces positive predictions, while lowering it generally increases them.

A Receiver Operating Characteristic (ROC) curve plots the true positive rate against the false positive rate at different thresholds. ROC-AUC measures the area under this curve. Under the usual score interpretation, it reflects how well the model ranks positive examples above negative examples.

Precision-recall curves plot precision against recall across thresholds. They are often particularly informative when positive examples are rare, although the baseline and interpretation depend on class prevalence.

Neither ROC-AUC nor PR-AUC automatically tells us which threshold should be deployed. The operational decision depends on the cost of errors, available resources and the required level of detection.

14.8.6 Regression Metrics

Regression models require metrics that measure numerical prediction errors.

Metric Meaning Important consideration
MAE Average absolute prediction error Expressed in the same units as the target.
MSE Average squared prediction error Penalises large errors strongly and has squared units.
RMSE Square root of MSE Returns to the target's units but remains sensitive to large errors.
R² Compares the model with a mean-based baseline under the usual definition Can be negative on test data; a high value does not guarantee small errors in every practical sense.

The coefficient of determination, R², is commonly written:

R² = 1 − SSres / SStot

SSres is the sum of squared residuals, and SStot is the total sum of squared deviations from the target mean. For a test set, R² can be negative when the model performs worse than the mean-prediction baseline according to this metric.

14.8.7 Evaluating Generative Models

Generative models are harder to evaluate because there may be no single correct output for a prompt. Several generated images or paragraphs may all be acceptable while differing considerably.

  • Image generation: Metrics such as Fréchet Inception Distance (FID) compare statistical features of generated and real images. The result depends on the feature extractor and evaluation setup.
  • Text generation: Perplexity measures how well a language model predicts held-out tokens. It does not directly measure factuality, usefulness or safety.
  • Machine translation: BLEU compares generated translations with reference translations using matching n-grams, but it may not fully capture meaning or fluency.
  • Question answering: Exact match, token-level F1, factual checks or expert judgement may be used depending on the task.
  • Human evaluation: People assess qualities such as relevance, readability, image realism and usefulness under a defined protocol.

For large language models, evaluation may include reasoning, coding, knowledge, instruction following, robustness, safety and tool use. Benchmark results can vary with prompts, data contamination, sampling settings and evaluation procedures. Scores should therefore be interpreted with their methodology in mind.

14.8.8 What Is Benchmarking?

Benchmarking means evaluating systems on a defined set of tasks, datasets, metrics and procedures so that their performance can be compared. A good benchmark should represent the intended application and allow results to be reproduced as far as practical.

A fair comparison requires more than putting two scores beside each other. Models should be evaluated using comparable data splits, preprocessing, metrics and computational conditions. When relevant, the comparison should also report training cost, inference latency, memory consumption and energy requirements.

Benchmark performance is not a complete measure of real-world value. A model that performs well on a public dataset may fail on unfamiliar data, and a tiny improvement in accuracy may not justify a major increase in computational cost.

Evaluation principle: Choose the metric according to the cost and meaning of mistakes in the actual problem. Never select a model using a metric merely because it produces an impressive-looking number.

The Complete Machine Learning Workflow

The topics in this chapter are parts of one connected process. In a real project, machine learning involves much more than selecting an algorithm and calling a training function.

Step 1: Define the Problem

First, decide what the system should predict or generate. Determine what a successful outcome means, who will use the result and what the cost of a wrong prediction would be. This decision influences the data, model and evaluation metrics.

Step 2: Collect and Understand the Data

Inspect the data for missing values, inconsistent formats, incorrect labels, duplicates and unusual distributions. Check whether the dataset represents the situations the deployed model will encounter.

Step 3: Split the Data

Create training, validation and test sets using a strategy appropriate to the problem. For time-series prediction, for example, a chronological split may be necessary to avoid training on future information when predicting the past. For related records from the same person or organisation, group-based splitting may be needed to prevent leakage.

Step 4: Prepare the Features

Transform the data into a form suitable for the model. This may include normalising numerical values, encoding categories, tokenising text or resizing images. Fit data-dependent transformations on the training set and apply the same fitted transformations to validation and test data.

Step 5: Establish a Baseline

Begin with a simple model or a straightforward rule. A baseline shows whether a more complex approach is actually providing value. For a numerical prediction problem, predicting the training target mean can be a useful basic baseline. For classification, a majority-class predictor can reveal whether an accuracy score is misleading.

Step 6: Train the Model

Select a suitable learning algorithm and loss function. For differentiable neural networks, calculate predictions, compute the loss, backpropagate gradients and update parameters using an optimiser.

Step 7: Tune and Validate

Compare model architectures, hyperparameters and regularisation choices using validation data. Investigate both training and validation performance to understand whether the model is underfitting or overfitting.

Step 8: Evaluate the Final Model

Once model selection is complete, evaluate the chosen model on the test set. Report the relevant metrics and investigate important failure cases. If the model will affect people, examine subgroup performance and potential fairness concerns where appropriate.

Step 9: Deploy and Monitor

A deployed model receives real inputs, consumes computing resources and influences decisions. Monitor data quality, latency, failure rates and predictive performance where labels become available. Detect distribution shifts and decide when retraining or replacement is needed.

A production lesson: A model with slightly lower offline accuracy may be preferable if it is much faster, cheaper, easier to maintain or more reliable under real operating conditions. Machine learning is both a statistical discipline and an engineering discipline.

Connecting Classical Machine Learning to Quantum Machine Learning

This book studies quantum computing, so an important question remains: why learn classical machine learning before studying quantum machine learning?

Quantum machine learning explores how quantum systems and quantum algorithms may help with learning tasks. To understand a proposed quantum method, we must first understand the classical problem it attempts to solve. Otherwise, it is difficult to decide whether the quantum approach offers a genuine advantage.

14.9.1 Classical Data and Quantum States

A classical machine learning model usually receives data represented by ordinary numbers, vectors, matrices or structured objects. A quantum algorithm operates on quantum states, which are prepared, transformed by quantum operations and measured.

One approach to quantum machine learning is to encode classical features into a quantum state. A parameterised quantum circuit then transforms that state, and measurements produce classical values that can be used in a learning objective.

The encoding process is important because a quantum computer does not automatically provide a cheap way to load an arbitrarily large classical dataset into a quantum state. State preparation, circuit execution and measurement can all contribute to the total cost.

14.9.2 Parameterised Quantum Circuits

A parameterised quantum circuit contains quantum gates whose operations depend on adjustable parameters. These parameters play a role similar to weights in a classical model, although the underlying computation is different.

Suppose a circuit depends on parameters θ and the measured observable has an expectation value:

f(θ, x) = ⟨ψ(θ, x)| O |ψ(θ, x)⟩

Here, x represents the input encoding, θ represents the circuit parameters, |ψ⟩ is the resulting quantum state and O is an observable that is measured. The expectation value is a numerical quantity associated with the measurement outcomes.

That output can be compared with a target using a classical loss function. An optimisation method then updates the circuit parameters. This produces a hybrid quantum-classical learning loop.

1. Encode: Prepare a quantum state using the classical input.
2. Process: Apply a parameterised quantum circuit.
3. Measure: Estimate one or more classical outputs from measurement results.
4. Calculate loss: Compare the output with the target using a classical objective.
5. Update: Use an optimiser to choose new circuit parameters, then repeat.

14.9.3 How the Concepts in This Chapter Transfer

Classical machine learning Quantum machine learning connection
Input features Classical data may be encoded into quantum states or used in a hybrid model.
Model parameters Quantum circuit rotation angles and other adjustable gate parameters.
Forward pass Prepare a state, apply quantum gates and estimate measurement outputs.
Loss function Compare measured predictions with targets using a suitable objective.
Gradient calculation Use suitable gradient estimators, such as parameter-shift methods for supported gates, or other optimisation strategies.
Optimiser A classical optimiser often updates the quantum circuit parameters.
Generalisation Test whether the learned quantum or hybrid model works on unseen examples.
Benchmarking Compare against strong classical baselines and include state preparation, measurement, runtime and hardware costs.

14.9.4 Does Quantum Machine Learning Always Outperform Classical Learning?

No. Quantum computers use quantum states and operations, but this does not mean that every learning task becomes faster or more accurate. A useful quantum advantage must be demonstrated for a clearly defined problem and under a fair comparison.

A convincing comparison should consider the classical algorithm's performance, the quantum data-encoding cost, the number of circuit executions, measurement noise, hardware limitations and the quality of the final answer. A theoretical advantage under special assumptions may not automatically translate into a practical advantage on today's hardware.

Classical machine learning provides the tools needed to design experiments, choose losses, train models and evaluate results. These same principles help us ask meaningful questions about quantum models.

The connection: Quantum machine learning changes parts of the computational machinery. It does not remove the need for good data, a meaningful objective, reliable optimisation, careful evaluation or evidence that the model is useful.

Chapter Summary

Machine learning is the study of algorithms that learn patterns from data and use those patterns to make predictions, discover structure or generate new examples. Its methods differ, but the same fundamental questions repeatedly appear: what is being learnt, what feedback is available, how is improvement measured and how do we know the result will work on new data?

  • Supervised learning learns from labelled examples and is commonly used for classification and regression.
  • Unsupervised learning discovers patterns or representations without supplied target labels in the basic setting.
  • Reinforcement learning learns decision-making strategies from rewards and interactions with an environment.
  • Loss functions quantify prediction errors, while optimisation searches for parameters that reduce the objective.
  • Gradient descent updates parameters using gradients, while backpropagation efficiently calculates neural network gradients.
  • Generalisation is the ability to perform well on unseen examples. Overfitting occurs when training performance does not transfer reliably.
  • Regularisation, representative data, careful validation and suitable model complexity can help reduce overfitting.
  • Kernel methods and SVMs provide principled approaches to classification and other learning problems, including non-linear ones.
  • Neural networks combine layers of mathematical operations to learn useful representations, while deep learning uses networks with multiple layers.
  • Generative models, including GANs, VAEs, diffusion models and autoregressive transformers, learn to produce new samples using different training and generation mechanisms.
  • Evaluation metrics must match the task. Accuracy, precision, recall, F1, regression errors and generative quality measures describe different aspects of performance.
  • Benchmarking requires fair experimental conditions, appropriate baselines and awareness of computational cost and real-world limitations.

The most important lesson is that training a model is not the same as proving that it is useful. A model must learn meaningful patterns, generalise beyond its training data and meet the requirements of the task for which it was built.

Show the numerical exercise answers

Accuracy:

(TP + TN) / Total = (30 + 55) / 100 = 85%

Precision:

TP / (TP + FP) = 30 / (30 + 10) = 75%

Recall:

TP / (TP + FN) = 30 / (30 + 5) ≈ 85.71%
