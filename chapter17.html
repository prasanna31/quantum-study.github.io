QUANTUM MACHINE LEARNING · CHAPTER 17

Parameterized Quantum Circuits as Models

How quantum circuits learn from data, how their parameters are trained, why gradients matter, and how to build a quantum classifier using PennyLane.

Introduction: Can a Quantum Circuit Learn?

Consider a simple problem. You are given information about a student's study hours and attendance, and you want to predict whether the student will pass an examination. You have examples from previous students, including their inputs and the correct outcomes. Your task is to construct a model that learns the relationship between the inputs and the outcomes.

A classical machine learning model might use a decision tree, logistic regression, or a neural network. These models contain adjustable values called parameters. Training changes these parameters until the model produces useful predictions.

A parameterized quantum circuit follows a similar idea. It uses quantum gates whose operations depend on adjustable numerical parameters. We supply data, run the circuit, measure the resulting quantum state, and use the measurement results to make predictions. Training then adjusts the gate parameters.

Such a circuit is commonly called a parameterized quantum circuit (PQC). When it is used as a trainable model, it is also often called a variational quantum circuit (VQC).

Central idea: A parameterized quantum circuit is not a machine that learns automatically merely because it uses qubits. It becomes a learning model when we define its inputs, adjustable parameters, prediction rule, loss function, and training procedure.

The important connection is this: quantum computing provides the circuit, machine learning provides the objective, and optimisation provides the method for improving the model.

17.1 Anatomy of a Variational Quantum Model

17.1.1 From a circuit to a model

A normal quantum circuit applies gates to qubits and eventually measures them. A variational circuit adds one important feature: some gates depend on parameters that we can change during training.

Let the input data be represented by a vector x, and let the trainable parameters be represented by θ (theta). The model can be written as follows:

f(x; θ) = quantum circuit output for input x and parameters θ

The semicolon separates the input from the trainable parameters. The input describes the example we want to classify, while the parameters describe the model's current learned behaviour.

Suppose we want to classify handwritten digits into two groups. The model receives features extracted from an image. These features are encoded into a quantum state, the circuit processes that state, and a measurement produces a number used to predict the class.

Each stage has a distinct responsibility. Keeping these responsibilities separate makes the design easier to understand and debug.

Part 1: Input data

The model begins with ordinary classical data. For example, an input could be a vector containing two numbers: x = (x₁, x₂). These numbers might describe two measurements of a physical system or two features of a customer.

Quantum circuits do not directly accept arbitrary real-valued vectors as quantum states. We must first transform the information into a representation that a quantum circuit can use.

Part 2: Data encoding

Data encoding converts classical information into quantum states or into parameters of quantum operations. One common approach is angle encoding, in which a data value determines the rotation angle of a gate.

For example, a single-qubit rotation around the Y-axis is written as RY(x). Its action depends on the input value x. Applying this gate to the initial state |0⟩ produces

RY(x)|0⟩ = cos(x/2)|0⟩ + sin(x/2)|1⟩

The input now influences the amplitudes of the quantum state. When we measure the qubit, the probabilities of observing 0 and 1 depend on x.

Encoding does not itself mean the model has learned anything. It merely provides a way for the input to enter the circuit. The trainable part of the circuit must learn how to use that information.

Part 3: Trainable quantum circuit

The trainable circuit contains quantum gates with adjustable parameters. For example, the circuit may contain rotations RY(θ₁), RZ(θ₂), and RY(θ₃). The parameters θ₁, θ₂, and θ₃ are initially assigned values, often randomly.

The circuit may also contain entangling gates such as CNOT. These gates allow the qubits to develop correlations that cannot always be described by treating each qubit independently.

The circuit's job is to transform the encoded state so that its measurement statistics become useful for the prediction task.

Part 4: Measurement

A quantum computer does not normally reveal the complete quantum state when we measure it. Instead, measurement returns an outcome sampled according to the probabilities specified by the state.

We can repeat the same circuit many times, called shots, and estimate an expectation value. For a Pauli-Z measurement on one qubit, the outcome is +1 for |0⟩ and -1 for |1⟩.

⟨Z⟩ = P(0) − P(1)

Since P(0) + P(1) = 1, the expectation value lies between -1 and +1. It can therefore serve as a simple numerical output from the quantum model.

Part 5: Prediction and loss

The measured expectation value is converted into a prediction. For a binary classification problem, we could interpret positive values as evidence for one class and negative values as evidence for the other. Alternatively, we can convert the value into a probability.

A loss function measures how far the prediction is from the correct answer. If the model repeatedly makes incorrect predictions, the loss will generally be high. If it produces useful predictions, the loss should decrease.

Training changes θ to reduce the loss. This completes the connection between quantum circuits and machine learning.

17.1.3 The mathematical model

Suppose the circuit contains a data-encoding operation U(x) followed by a trainable operation U(θ). Its action on the initial state can be represented as

|ψ(x, θ)⟩ = U(θ)U(x)|0...0⟩

Here, |0...0⟩ represents a register of qubits initially prepared in the all-zero state. U(x) encodes the input, and U(θ) transforms the encoded state using trainable gates.

If we measure an observable O, the model output is

f(x; θ) = ⟨ψ(x, θ)|O|ψ(x, θ)⟩

This expression is an expectation value. It tells us the average measurement result predicted by the quantum state. In practice, a finite number of measurements provides an estimate of this value.

Given a dataset of input-output pairs (xᵢ, yᵢ), training aims to minimise a loss such as

L(θ) = (1/N) Σᵢ ℓ(f(xᵢ; θ), yᵢ)

The symbol N is the number of training examples, and ℓ is the loss for a single example. This is the same basic optimisation structure used in classical machine learning.

Important distinction: The quantum circuit calculates the model output. The loss function judges the output, and the optimiser decides how the parameters should change. These are three different responsibilities.

17.1.4 What is an ansatz?

An ansatz is a chosen structure for a quantum circuit whose parameters can be adjusted. The word is used in physics and mathematics for a proposed form of a solution.

For a variational quantum model, an ansatz specifies which gates are used, the order in which they appear, which qubits they act on, and where trainable parameters are placed.

For example, a simple ansatz might apply a trainable rotation to each qubit and then use CNOT gates to entangle neighbouring qubits. Repeating these operations creates multiple layers.

The ansatz determines which quantum states the circuit can reach. A circuit that is too restricted may be unable to represent the patterns in the data. A circuit that is unnecessarily complicated may be difficult to train and expensive to execute.

Designing an ansatz is therefore similar to choosing the architecture of a classical neural network. It determines the model's capabilities before training begins.

17.2 Quantum Models as Fourier Series

17.2.1 Why does a quantum model resemble a wave?

Quantum mechanics is closely connected to waves. Quantum states contain complex amplitudes, and quantum gates change the relationships between these amplitudes. When a state is measured, the resulting probabilities depend on these changes.

Rotation gates are especially important in quantum machine learning because their matrix entries contain sine and cosine functions. When data values determine rotation angles, the resulting measurement probabilities can depend on those data through trigonometric functions.

This creates a surprising connection: some quantum models behave mathematically like Fourier models, which represent functions using combinations of sine and cosine waves.

17.2.2 A simple one-qubit example

Begin with a qubit in the state |0⟩. Apply a Y-axis rotation whose angle is the input x:

RY(x)|0⟩ = cos(x/2)|0⟩ + sin(x/2)|1⟩

Now measure the qubit in the computational basis. The probabilities of observing the two outcomes are

P(0) = cos²(x/2)
P(1) = sin²(x/2)

The expectation value of Pauli-Z is therefore

f(x) = P(0) − P(1) = cos(x)

The model output varies like a cosine wave. This is a direct example of a quantum circuit implementing a periodic function.

A single cosine is not a very flexible model. However, more complicated circuits can produce combinations of multiple frequencies. Trainable parameters influence the coefficients and the way the circuit combines these contributions.

17.2.3 What is a Fourier series?

A Fourier series represents a periodic function as a sum of sine and cosine components. In complex notation, it can be expressed as

f(x) = Σₖ cₖ eikx

Here, k represents a frequency index, and cₖ represents the coefficient associated with that frequency. For a real-valued function, the coefficients have the relationships required to make the final result real.

Imagine trying to describe a complicated sound. Instead of describing every movement of the sound wave directly, we can describe it as a combination of simpler waves at different frequencies. Fourier analysis uses this idea to understand signals.

A similar idea can be used for a function learned by a quantum circuit. Its output can sometimes be expressed as a Fourier-like expansion over the input variables.

17.2.4 Where do the frequencies come from?

Consider a circuit whose data encoding uses rotations such as RY(x). Each occurrence of the input-dependent gate contributes to the possible frequency structure of the final expectation value.

The exact frequencies depend on the encoding gates, the generators of those gates, how many times data is encoded, and how the circuit operations are arranged. The available frequencies are not arbitrary; the circuit structure imposes restrictions on them.

If data is encoded only once in a very simple circuit, the resulting function may contain only a small number of frequency components. Repeated data encoding can expand the set of frequencies that the model can represent.

This is one reason data re-uploading is useful. The circuit can repeatedly receive the same input while applying different trainable operations between encoding steps.

17.2.5 A practical illustration

Suppose the target function is more complicated than a single cosine. A simple model might struggle to reproduce it. A model with more accessible frequency components could potentially approximate it more accurately.

For example, a target function might contain a slow variation and a rapid variation at the same time. These correspond to lower and higher frequencies. A circuit that can represent only the lower frequency may miss the rapid changes.

This suggests a useful design principle: choose the data encoding and circuit structure with the target function in mind. Adding more layers may expand the available function space, but it does not guarantee better learning.

A necessary qualification: The statement that quantum models are Fourier series is not a claim that every quantum circuit has the same frequencies or that every target function is easy to learn. Fourier descriptions are especially useful for particular data-encoding schemes, including parameterised rotation encodings.

17.2.6 Why this connection matters

Viewing a quantum circuit as a Fourier model helps researchers understand its expressive power. It explains how circuit depth, encoding choices, and repeated data injection affect the functions the circuit can represent.

It also gives a way to study a quantum model without relying only on numerical experiments. We can ask which frequencies are available, which are missing, and how difficult it is to learn the coefficients associated with them.

However, representing a function and learning that function efficiently are different challenges. A model may theoretically contain the right frequency components but still be difficult to train with noisy measurements and limited computational resources.

17.3 Expressibility and Entangling Capability

17.3.1 What does it mean for a model to be expressive?

Imagine two artists who are asked to draw a landscape. One artist knows only how to draw straight lines, while the other can draw curves, shadows, textures, and complex shapes. The second artist has a larger set of possible drawings.

In machine learning, this ability to represent different patterns is called expressibility. For a parameterized quantum circuit, expressibility describes the range of quantum states or functions the circuit can represent as its parameters vary.

A circuit with one rotation gate and no other operations has limited possibilities. A circuit with multiple rotation layers and entangling gates can usually represent a broader collection of states.

Yet a larger collection of possible states does not automatically make a model better. A useful model must represent the patterns needed by the task and must also be trainable with the available resources.

17.3.2 The role of circuit depth

Circuit depth refers roughly to the number of sequential layers of quantum operations. Gates acting independently on separate qubits can sometimes run in parallel, so depth is not simply the total number of gates.

Increasing depth can allow the circuit to perform more complicated transformations. More trainable rotations create more adjustable degrees of freedom, and additional entangling operations can create richer relationships between qubits.

However, deeper circuits require more operations and may suffer more from hardware noise. They can also create difficult optimisation landscapes in which gradients become extremely small.

This means that increasing depth is a trade-off rather than an unconditional improvement.

17.3.3 Entanglement and correlations

A system of two qubits can be in a product state, meaning its state can be written as the state of the first qubit multiplied by the state of the second. In such a state, the two qubits have no quantum entanglement.

An entangled state cannot be written as a product of independent single-qubit states. Its properties must be described using the joint system.

For example, begin with two qubits in |00⟩. Apply a Hadamard gate to the first qubit and then a CNOT gate controlled by the first qubit. The resulting state is

|ψ⟩ = (|00⟩ + |11⟩)/√2

This is a Bell state. Measuring both qubits in the computational basis produces either 00 or 11, each with probability one-half. The outcomes are perfectly correlated in this measurement basis.

Entanglement can allow a circuit to represent joint quantum states that cannot be produced by independent single-qubit operations alone. This can be useful when the learning task depends on relationships between several features.

Nevertheless, entanglement is not a magic ingredient that guarantees a quantum advantage. Some classical models can represent the same task efficiently, and some quantum tasks do not need entanglement to achieve good results.

17.3.4 What is entangling capability?

Entangling capability describes how effectively a circuit structure can generate entangled states. It depends on the arrangement of gates, the number of qubits, the topology of their connections, and the range of parameter values.

A circuit may contain CNOT gates yet still produce little entanglement for certain parameter settings. Conversely, a carefully designed circuit can generate useful entanglement without needing a very large number of gates.

Entangling capability is therefore related to circuit design, not merely to counting how many entangling gates appear in the circuit.

17.3.5 Measuring expressibility

There is no single universal measurement of expressibility that is best for every circuit and task. One common approach is to sample many parameter settings, generate the resulting quantum states, and compare their distribution with a chosen reference distribution, such as the Haar distribution over pure quantum states.

The Haar distribution describes a mathematically natural, uniform distribution over quantum pure states. For small systems, researchers can compare the statistics of sampled states with Haar-random states using measures based on state overlaps or probability distributions.

Such comparisons require care. A circuit that closely resembles a Haar-random state generator may be highly expressive according to one measure, but that does not mean it is well suited to a particular classification problem.

17.3.6 The barren plateau problem

Here is a major difficulty. A highly expressive circuit can sometimes be extremely difficult to train because the gradients of its loss function become very small.

If the gradient is almost zero, changing the parameters produces little measurable improvement in the loss. The optimiser may struggle to identify a useful direction. This phenomenon is associated with barren plateaus.

Barren plateaus can arise under several conditions, including certain random circuit constructions and cost functions. Their severity depends on the circuit, the observable, the number of qubits, and the training setup. They are not inevitable in every variational quantum model.

The lesson is important: a model needs enough expressive power to learn the task, but it should not be made unnecessarily complicated. Shallow, structured circuits, local cost functions, and sensible initialisation can help in some settings.

Design property Potential benefit Possible difficulty
More layers Can represent more complex transformations Greater noise and potentially harder optimisation
More trainable parameters More freedom to fit the training data More values to optimise and possible overfitting

Design principle: The best circuit is not necessarily the deepest or the most expressive. It is the circuit that can represent the relevant patterns and can be trained reliably under the available hardware and measurement constraints.

17.4 Gradient Computation: Parameter-Shift Rule and Beyond

17.4.1 Why does training need gradients?

Suppose a model has three trainable parameters: θ₁, θ₂, and θ₃. We calculate its loss and find that the current prediction is incorrect. We now need to decide how to change the three parameters.

A gradient tells us how sensitive the loss is to each parameter. If the derivative with respect to θ₁ is large, a small change in θ₁ may have a noticeable effect on the loss. If the derivative is close to zero, a small change may have very little effect at the current point.

For a loss function L(θ), the gradient is

∇L(θ) = (∂L/∂θ₁, ∂L/∂θ₂, ..., ∂L/∂θₘ)

A basic gradient descent update is

θ ← θ − η∇L(θ)

Here, η is the learning rate. It determines the size of each update. The minus sign means that we move in the direction that locally decreases the loss.

Classical neural networks calculate gradients using backpropagation. Quantum circuits need a way to estimate derivatives of functions that are obtained through quantum operations and measurements.

17.4.2 The basic idea of the parameter-shift rule

One approach is to change a parameter slightly in both directions, measure the resulting outputs, and estimate the derivative. This resembles the finite-difference method from numerical mathematics.

For a function f(θ), a central finite-difference estimate is

f′(θ) ≈ [f(θ + ε) − f(θ − ε)]/(2ε)

The approximation becomes more accurate for suitable small values of ε, although very small values can make numerical or measurement noise more troublesome.

Quantum rotation gates have a useful mathematical property. For common gates generated by suitable Pauli operators, we can calculate the derivative exactly using shifted evaluations of the quantum circuit rather than relying on an arbitrarily small finite-difference step.

∂f/∂θ = [f(θ + π/2) − f(θ − π/2)]/2

This is the standard two-evaluation parameter-shift rule for common Pauli-generated rotation gates when the parameter and gate convention satisfy its assumptions. The shift is π/2, and the difference is divided by two.

The result is an exact derivative of the ideal expectation value in exact arithmetic. On real quantum hardware, however, each expectation value is estimated from finite measurements, so the resulting gradient still has statistical uncertainty.

17.4.3 A numerical example

Consider the function f(θ) = cos(θ). Its derivative is f′(θ) = −sin(θ). At θ = π/3, the exact derivative is −√3/2, approximately −0.866.

Apply the parameter-shift rule:

f′(π/3) = [cos(π/3 + π/2) − cos(π/3 − π/2)]/2

= [cos(5π/6) − cos(−π/6)]/2

= [−√3/2 − √3/2]/2

= −√3/2

The shifted evaluations recover the exact derivative without taking a tiny numerical step.

17.4.4 Why can this work on quantum hardware?

The rule comes from the mathematical structure of the parameterised gate. For a suitable rotation generated by a Pauli operator, the expectation value as a function of that gate's parameter has a restricted trigonometric form. Differentiating this form leads to the shifted evaluation formula.

A quantum computer does not need to expose the internal amplitudes of its state. It only needs to run the circuit with the shifted parameter values and measure the observable. The classical training code combines those measured results to obtain the gradient estimate.

This is particularly useful when the quantum device acts as a black box: the classical optimiser can still learn how the output changes as the circuit parameters change.

17.4.5 What if a parameter appears more than once?

If the same parameter is used in multiple gate occurrences, care is required. A derivative with respect to that parameter includes the contributions from every occurrence. One safe conceptual approach is to differentiate each occurrence and add the resulting contributions.

For gates with generators having more than two distinct eigenvalues, the simple two-shift formula may not apply directly. Generalised parameter-shift rules can use multiple shifted evaluations with appropriate shifts and coefficients.

Thus, the parameter-shift rule is a family of derivative methods, not one universal formula that can be applied unchanged to every parameterised quantum operation.

17.4.6 Other ways to calculate gradients

Finite differences

Finite differences estimate the derivative by evaluating the circuit at nearby parameter values. They are easy to understand and can be useful for checking implementations. However, they introduce a step-size choice and can be sensitive to shot noise.

Adjoint differentiation

Some quantum simulators can calculate gradients using adjoint differentiation. Instead of independently evaluating shifted circuits for every parameter, the simulator uses the structure of the state evolution to compute derivatives more efficiently.

The precise cost depends on the simulator, circuit representation, number of parameters, and measured quantities. Adjoint methods are often attractive for statevector simulations but are not automatically available in the same form on hardware-only devices.

Backpropagation through a simulator

A classical quantum simulator represents the circuit using numerical arrays and operations. Automatic differentiation tools can differentiate many of these operations, allowing a developer to use familiar optimisation frameworks.

This is conceptually close to classical deep learning. However, differentiating a simulation of a quantum circuit is not the same as directly differentiating unknown hardware states. Hardware measurements still require appropriate gradient-estimation procedures.

Method How it works Important limitation
Parameter-shift Uses mathematically chosen shifted circuit evaluations Requires the appropriate shift rule for each operation
Finite difference Estimates a derivative from nearby evaluations Step size and measurement noise affect accuracy
Adjoint differentiation Uses simulator state evolution to calculate derivatives Depends on simulator capabilities and supported measurements
Automatic differentiation Propagates derivatives through supported numerical operations Hardware measurements need a compatible differentiation method

17.4.7 The cost of gradients

A quantum circuit's output may be estimated using many repeated measurements. If the model has numerous parameters, calculating a full gradient can require many circuit evaluations.

With a straightforward parameter-shift implementation, each parameter occurrence can require multiple shifted evaluations. The total cost also depends on the number of training examples, the number of shots per evaluation, and the circuit depth.

For this reason, training a small model on a simulator may be straightforward, while training a large model on real quantum hardware can be much more demanding.

Key lesson: Gradient calculation makes variational circuits trainable, but gradients are not free. Measurement cost, circuit depth, noise, and the number of parameters all influence how practical training will be.

17.5 Quantum Natural Gradient

17.5.1 Why ordinary gradient descent may not be enough

Ordinary gradient descent assumes that a small numerical change in each parameter provides a useful description of a small step in the model's behaviour. This is a convenient approximation, but it ignores the geometry of the model's parameter space.

Consider two parameters in a quantum circuit. Changing the first parameter by 0.01 might change the quantum state considerably, while changing the second by 0.01 might barely change it. The same numerical step can therefore have different physical effects.

There is another complication: different parameter settings can sometimes describe the same quantum state or nearly the same observable behaviour. The parameter space can contain redundancies and curved directions.

Quantum natural gradient methods take this geometry into account when deciding how parameters should change.

17.5.2 Understanding the geometry of quantum states

A quantum state is represented by a vector of complex amplitudes, but physically equivalent descriptions can differ by a global phase. Furthermore, two states may be close in terms of their physical distinguishability even when their parameter values are not numerically close.

The geometry of quantum states can be studied using quantities such as fidelity and the quantum geometric tensor. Fidelity measures how similar two quantum states are. For pure states |ψ⟩ and |φ⟩, their fidelity is commonly written as

F = |⟨ψ|φ⟩|²

Fidelity equals one for identical pure states and decreases as the states become less similar.

This gives us a way to ask a useful question: if we change a parameter slightly, how much does the physical quantum state change?

17.5.3 The quantum geometric tensor

For a parameterised pure state |ψ(θ)⟩, the quantum geometric tensor describes how the state changes as the parameters change. Its real part is closely related to the quantum Fisher information metric. Under common conventions, the corresponding metric is written as

Gᵢⱼ = Re( ⟨∂ᵢψ|∂ⱼψ⟩ − ⟨∂ᵢψ|ψ⟩⟨ψ|∂ⱼψ⟩ )

Here, ∂ᵢψ denotes the derivative of the state with respect to parameter θᵢ. The subtraction removes the component associated with a change that does not alter the physical state beyond a global phase.

Conventions differ across the literature, particularly in whether a factor of four is included in the metric. The central idea remains the same: the metric measures the distinguishable change in a quantum state caused by changes in its parameters.

17.5.4 The natural-gradient update

Ordinary gradient descent uses the gradient directly. Quantum natural gradient instead rescales or transforms the gradient using a metric that describes the geometry of the quantum state space.

θ ← θ − η G⁻¹ ∇L(θ)

In this expression, G is the metric matrix, ∇L is the loss gradient, and η is the learning rate. The inverse metric changes the direction and scale of the update according to how parameter changes affect the state.

This resembles a preconditioned optimisation method: the update is adjusted so that the optimiser accounts for differences in the sensitivity and geometry of different parameter directions.

If G is singular or poorly conditioned, directly inverting it can be unstable. Practical implementations may use a regularised matrix such as G + λI, where λ is a small positive value and I is the identity matrix.

17.5.5 A simple intuition

Imagine walking on a hilly landscape. On a flat map, moving one centimetre east and one centimetre north seems equally straightforward. On the actual terrain, however, one direction may lead up a steep slope while another follows a gentle path.

Ordinary gradient descent uses the local slope to choose a direction in parameter coordinates. A natural gradient also considers how those coordinates relate to changes in the underlying model.

In a quantum circuit, the underlying model is the quantum state and its measurement behaviour. The natural gradient tries to make optimisation steps more meaningful with respect to that geometry.

17.5.6 Why not always use quantum natural gradient?

Computing and solving systems involving the metric matrix can be expensive. With many trainable parameters, the matrix can be large, and estimating its entries may require additional quantum circuit evaluations.

Regularisation, approximation, and circuit-specific structure can reduce the cost, but they introduce further implementation choices.

Quantum natural gradient can improve optimisation in some situations, but it is not guaranteed to outperform ordinary gradient descent or adaptive optimisers. The correct choice depends on the model, the cost of estimating the metric, and the available resources.

Remember the distinction: The ordinary gradient tells us how the loss changes with the parameters. The quantum natural gradient also considers how the parameters describe changes in the quantum state.

17.6 Hybrid Quantum-Classical Training Loops

17.6.1 Why do we need a hybrid system?

A quantum circuit is good at performing quantum operations, but an entire machine learning workflow involves much more than executing gates. We need to store datasets, calculate losses, choose optimisation algorithms, update parameters, and evaluate predictions.

Classical computers already perform these tasks efficiently and have mature software libraries for them. Variational quantum machine learning therefore commonly combines a classical computer with a quantum processor or simulator.

The classical computer controls the experiment and processes the results. The quantum device evaluates the parameterised circuit. The two systems repeatedly exchange numerical information during training.

The procedure begins by choosing initial parameters. The quantum circuit is executed using these parameters, and the measurement results are returned to the classical program. The program calculates the loss and estimates its gradient with respect to the parameters.

The optimiser then updates the parameters. The circuit runs again with the new values, and the process repeats until a stopping condition is reached.

A stopping condition might be a sufficiently low loss, a maximum number of training iterations, or the absence of meaningful improvement over several iterations.

17.6.3 What happens in one iteration?

  1. Select a batch of examples. The classical computer selects one or more training examples and their correct labels.
  2. Encode each input. The input values determine the data-dependent gates or other encoding operations.
  3. Execute the parameterised circuit. The circuit uses the current trainable parameters and produces measurement samples or expectation values.
  4. Calculate the loss. The classical program compares the predictions with the correct labels.
  5. Calculate the gradient. A compatible differentiation method estimates how the loss changes with each parameter.
  6. Update the parameters. The optimiser uses the gradient to generate a new parameter vector.
  7. Repeat. The updated circuit is evaluated again until training stops.

17.6.4 Why use mini-batches?

Suppose the dataset contains ten thousand examples. Evaluating every example during every update can be expensive. Instead, the classical optimiser can use a smaller batch of examples to estimate the direction of improvement.

This is the same general idea used in classical mini-batch stochastic gradient descent. It can reduce the amount of work required for an update, although the resulting gradient is noisier because it is estimated from fewer examples.

Quantum training has another source of noise: the measurement process itself. A small batch and a small number of measurement shots can produce a particularly noisy estimate. Choosing batch size and shot count is therefore an important practical decision.

17.6.5 The role of measurement shots

Suppose we estimate an expectation value by running the same circuit 100 times. The observed average will generally differ from the exact expectation value. If we increase the number of independent shots, the statistical uncertainty of a simple sample average typically decreases in proportion to the inverse square root of the shot count.

Standard error ∝ 1/√S

Here, S is the number of shots, assuming independent samples with a fixed underlying distribution.

This means that reducing the statistical error by approximately a factor of two generally requires about four times as many shots. The exact costs of an experiment depend on the hardware and the measurement procedure.

Too few shots can make the loss and gradient estimates unreliable. Too many shots can make training slow and expensive. The right balance depends on the accuracy needed at each stage of optimisation.

17.6.6 Simulator versus real quantum hardware

During development, it is common to start with a simulator. A simulator makes it easy to inspect circuit behaviour, test gradients, and run repeated experiments without waiting for access to physical hardware.

An ideal statevector simulator can calculate quantum states and expectation values accurately within numerical precision, subject to the limitations of the simulator and the size of the system. A finite-shot simulation introduces sampling uncertainty. A noisy simulator can additionally model specified hardware errors.

Real devices introduce physical noise, calibration variation, connectivity restrictions, queueing delays, and execution costs. A model that trains well on an ideal simulator may behave differently on hardware.

A sensible development process is to validate the mathematics on a simulator, test finite-shot behaviour, investigate realistic noise, and only then move to hardware when appropriate.

17.6.7 Why hybrid does not automatically mean faster

A hybrid model has additional communication and execution costs. Gradient calculation may require many circuit evaluations, and real devices may take considerable time to return measurement results.

Therefore, using a quantum processor does not automatically make a machine learning problem faster. A convincing advantage requires a fair comparison against strong classical methods, including the costs of data encoding, circuit execution, measurements, and classical processing.

Practical lesson: A hybrid quantum-classical model is an optimisation workflow distributed across two kinds of computing resources. Its usefulness depends on the complete workflow, not just the quantum circuit.

The example uses a simulator so that it can run on an ordinary computer without access to a quantum processor. The code uses a hybrid training loop: PennyLane evaluates the circuit and calculates derivatives, while a classical optimiser updates the parameters.

The goal is not to demonstrate quantum advantage. It is to understand how the components of a variational model fit together in working code.

17.7.3 Define the dataset

We will create a small, two-dimensional dataset. Each example has two features, and its label is either -1 or +1. The features are deliberately simple so that we can focus on the quantum model rather than on data processing. 

import pennylane as qml
from pennylane import numpy as np

# Two numerical features per example.
X = np.array([
    [-0.80, -0.70],
    [-0.60, -0.90],
    [-0.90, -0.40],
    [-0.40, -0.60],
    [ 0.70,  0.80],
    [ 0.90,  0.50],
    [ 0.50,  0.90],
    [ 0.80,  0.40],
], requires_grad=False)

# The two classes are represented by -1 and +1.
y = np.array(
    [-1, -1, -1, -1, 1, 1, 1, 1],
    requires_grad=False
)

print("Dataset shape:", X.shape)
print("Number of examples:", len(y))

The dataset has eight examples and two features per example. Four examples belong to the negative class, and four belong to the positive class.

In a real project, the dataset would need suitable preprocessing, feature scaling, and separate training and testing sets. The small dataset here is only a demonstration of the training mechanics.

17.7.4 Create the quantum device

PennyLane represents a quantum execution target as a device. The device specifies where the circuit runs and how its operations are evaluated. 

n_qubits = 2
n_layers = 2

dev = qml.device(
    "default.qubit",
    wires=n_qubits
)

We use two qubits because our example contains two features. This is a convenient design choice, not a general requirement that the number of features must equal the number of qubits. Other encoding strategies can map more features to a smaller or larger quantum register.

17.7.5 Design the variational circuit

The circuit has three main stages. First, we encode the input features using Y-axis rotations. Next, we apply trainable rotation gates and a CNOT entangling operation. Finally, we measure Pauli-Z on the first qubit. 

@qml.qnode(dev, interface="autograd")
def quantum_model(x, weights):
    # Stage 1: Encode the two classical features.
    qml.RY(x[0], wires=0)
    qml.RY(x[1], wires=1)

    # Stage 2: Trainable layers.
    for layer in range(n_layers):
        qml.RY(weights[layer, 0], wires=0)
        qml.RZ(weights[layer, 1], wires=0)

        qml.RY(weights[layer, 2], wires=1)
        qml.RZ(weights[layer, 3], wires=1)

        # Entangle the two qubits.
        qml.CNOT(wires=[0, 1])

    # Stage 3: Return an expectation value.
    return qml.expval(qml.PauliZ(wires=0))

The decorator @qml.qnode tells PennyLane to construct a quantum node. The interface setting allows the quantum computation to work with PennyLane's automatic differentiation system.

Each trainable layer has four parameters. Two control rotations on the first qubit, and two control rotations on the second. Since there are two layers, the model has eight trainable parameters.

The CNOT gate introduces an interaction between the qubits. The measured expectation value is a real number between -1 and +1, which will be used as the model's prediction score.

17.7.6 Inspect the circuit

Before training, it is useful to inspect the circuit generated by PennyLane. A diagram makes the order of operations easier to understand. 

initial_weights = np.array(
    np.random.uniform(
        low=-0.1,
        high=0.1,
        size=(n_layers, 4)
    ),
    requires_grad=True
)

print(
    qml.draw(quantum_model)(
        X[0],

)

The diagram will show the input rotations, the trainable gates, the CNOT gates, and the final measurement. The precise printed representation can vary by PennyLane version.

17.7.7 Convert the circuit output into a loss

We need a rule that tells the optimiser whether the circuit is making useful predictions. Since our labels are -1 and +1, we can use a simple squared-error loss.

L(θ) = (1/N) Σᵢ [f(xᵢ; θ) − yᵢ]²

When the model output is close to the correct label, the contribution to the loss is small. When the output is far from the label, the contribution is larger. 

def predict_one(x, weights):
    return quantum_model(x, weights)


def loss_function(weights, X_batch, y_batch):
    predictions = np.stack([
        predict_one(x, weights)
        for x in X_batch
    ])

    errors = predictions - y_batch

    return np.mean(errors ** 2)

This loss is appropriate for our simple score-based demonstration. It should not be confused with a universal loss for quantum classification. If a model produces class probabilities, cross-entropy may be more appropriate. If we use different output conventions, the labels and loss must be adjusted accordingly.

17.7.8 Train the model

We can now use a classical optimiser to adjust the circuit parameters. PennyLane provides interfaces for calculating gradients of supported quantum functions. The following code uses GradientDescentOptimizer. 

# Initialise trainable parameters.
weights = np.array(
    np.random.uniform(
        low=-0.1,
        high=0.1,
        size=(n_layers, 4)
    ),
    requires_grad=True
)

optimizer = qml.GradientDescentOptimizer(
    stepsize=0.2
)

epochs = 60

for epoch in range(epochs):
    weights, current_loss = optimizer.step_and_cost(
        lambda w: loss_function(w, X, y),
        weights
    )

    if epoch % 10 == 0 or epoch == epochs - 1:
        print(
            f"Epoch {epoch:02d} | "
            f"Loss: {float(current_loss):.6f}"
        )

At each iteration, PennyLane differentiates the loss with respect to the trainable parameters using the selected device and differentiation configuration. The optimiser then changes the parameters to reduce the loss.

On the ideal simulator, the default analytic expectation-value evaluation can avoid finite-shot sampling noise. The exact gradient calculation method depends on the device, interface, and differentiation settings. Parameter-shift is one common approach, but it should not be assumed that every PennyLane configuration uses it automatically.

The printed loss should be inspected rather than assumed to decrease on every iteration. Optimisation is not guaranteed to succeed from every random initialisation, and the final outcome can depend on the learning rate, circuit structure, and dataset.

17.7.9 Evaluate predictions

After training, we can inspect the model outputs and convert each score into a class prediction. For this example, scores greater than or equal to zero predict +1, while negative scores predict -1. 

predictions = np.stack([
    quantum_model(x, weights)
    for x in X
])

predicted_labels = np.where(
    predictions >= 0,
    1,
    -1
)

accuracy = np.mean(
    predicted_labels == y
)

print("Scores:")
print(predictions)

print("Predicted labels:")
print(predicted_labels)

print("Training accuracy:", float(accuracy))

Training accuracy tells us how many training examples the model classified correctly. It does not tell us how well the model will perform on unseen examples.

To evaluate generalisation, a proper experiment should use a separate test set or cross-validation. For a very small dataset, measured accuracy can also change substantially with the chosen examples and initial parameters.

17.7.11 Understanding the complete workflow

Let us connect the code back to the theory. The array X supplies the classical input data, and y supplies the labels. The first pair of rotations encodes each input into the quantum state.

The array weights stores the trainable parameters. Each execution of quantum_model produces an expectation value. The loss function compares these values with the correct labels.

The optimiser requests a gradient and uses it to update the parameters. Repeated executions of the circuit therefore change the prediction function, ideally making it better at separating the two classes.

This is the essential structure of a variational quantum classifier. Larger models may use more qubits, more layers, different encodings, different observables, or more sophisticated classical optimisers, but the basic training loop remains recognisable.

17.7.12 How to improve the experiment

Once the basic model works, change one design decision at a time and compare the results. This is a better way to understand the model than changing every part simultaneously.

  • Change circuit depth. Try one, two, and three layers. Observe whether additional parameters help the model or make optimisation less stable.
  • Change the learning rate. A learning rate that is too large may produce unstable updates, while one that is too small may lead to slow progress.
  • Change the entangling pattern. Compare the CNOT arrangement with a circuit containing no entangling gates. This helps investigate whether the chosen task benefits from interactions between qubits.
  • Change the encoding. Try a different rotation axis or repeated data encoding. Keep the input range sensible and compare the resulting learning behaviour.
  • Change the optimiser. Compare gradient descent with an adaptive optimiser supported by the installed PennyLane version.
  • Test generalisation. Use a held-out dataset rather than evaluating only the examples used during training.
  • Introduce finite shots. Configure the simulator to use a finite number of shots and observe how measurement uncertainty affects predictions and gradients.

These experiments reveal an important fact: quantum machine learning is not only about inventing new circuits. It also requires careful experimental design, numerical analysis, debugging, and fair evaluation.

Chapter Summary

A parameterized quantum circuit becomes a machine learning model when classical data is encoded into the circuit, trainable gates transform the quantum state, measurements produce outputs, and an optimiser adjusts the parameters to minimise a loss.

The model's mathematical behaviour is influenced by its data encoding and gate structure. For suitable encoding schemes, its outputs can be understood through Fourier-like expansions. Circuit depth and entangling operations influence the range of states and functions that the model can represent.

Expressibility alone is not enough. A circuit must also be trainable. Excessively difficult optimisation landscapes, small gradients, finite measurement precision, and hardware noise can make training challenging.

The parameter-shift rule provides a principled method for calculating derivatives of suitable parameterised quantum circuits. Quantum natural gradient methods go further by considering the geometry of the quantum state space. Both approaches can be useful, but their computational costs and assumptions matter.

Finally, hybrid quantum-classical training combines quantum circuit execution with classical loss calculations and optimisation. PennyLane provides tools for constructing these workflows, differentiating supported circuits, and testing quantum models on simulators and compatible hardware.
